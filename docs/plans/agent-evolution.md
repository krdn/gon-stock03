# gon-stock03 기능 검증과 코딩 에이전트 자기개선 설계

**제안.** 기존 테스트를 기능별로 묶고, Astra가 재현 가능한 오류를 수정하거나 채택된 기능을 구현해 PR로 제출하게 한다. 작업을 마칠 때마다 실패 원인에서 프로젝트 전용 작업 지침 후보를 하나 만든다. 다음 세대에 쓸 지침은 기존 버전과 동일 조건으로 경쟁시킨다. 앱 변경과 에이전트 변경은 각각 되돌릴 수 있다. 첫 실험은 실제 수정 전후가 남은 관심종목 회귀다.

2026-11-19 기준 main `544bd75`의 단위·통합 271건, Chromium 브라우저 170건이 CI에서 통과했다. 테스트 파일은 각각 22개와 19개다. 브라우저는 포트 4314, 단일 worker, 메모리 DB를 쓴다. 기능표의 출발점은 15개 화면의 목적·실패·수용 조건을 이미 담은 레지스트리와 별도 매매 설정 경로다. 통과 건수로 상태별 누락을 알 수는 없다. 기존 CI만으로도 회귀 검사는 가능하다. 부족한 부분은 어떤 사용자 동작이 미검증인지, 변경 전에도 검사가 통과하는지, 지침을 바꿨을 때 **새 과제도 더 잘 푸는지**다. 반대로 전체 Evolve 루프를 기본값으로 가동하면 출하·권한·모델 배정까지 함께 바뀌어 원인을 비교하기 어렵다. 이 설계는 변경 요인 하나와 그 효과를 먼저 측정한다. 논문의 벤치마크 성적은 프로젝트 목표치에 사용하지 않는다.

## 제품 변경 한 건의 흐름

1. **선택.** 기능표에 연결한 사용자 보고, CI 실패, 미검증 조건을 수집한다. 같은 기능·동작·실패 서명은 기존 이슈에 합친다. 재현 가능한 회귀, 동작 증거의 공백, 채택된 작은 기능 순으로 한 건을 선택한다. 자동 탐색은 순환 순서로 오래 검사하지 않은 기능을 고르고, 한 바퀴마다 기능별 잔여를 보여준다. 처리할 항목이 없으면 종료한다.
2. **오류 수정.** 동작 계약과 기준 SHA를 고정하고 신뢰된 실행기에서 같은 입력의 실패를 확인한다. 현재 기준본이 통과하면 중복·수정 완료 여부를 본다. 환경 오류와 비결정적 실패는 따로 분류한다. Astra는 격리 복사본에서 최소 패치와 회귀 테스트를 작성한다.
3. **새 기능.** 에이전트가 불편한 작업 동선·반복된 요청에서 사용 사례, 예상 이득, 영향을 받는 화면, 수용/거부 예시를 이슈로 제안한다. 채택된 이슈에 대해서만 동작을 구현한다. 예시 후보는 관심종목 상세에서 **선택한 종목코드만 복사**하는 기능이다. 수용 예시는 선택 변경 직후 정확한 코드, 복사 권한 거부 시 안내, 주문 요청 0건이다. 실제 수요·우선순위는 미측정이다.
4. **판정과 전달.** 후보가 쓴 테스트 외에 평가자가 고정한 동작 검사, 기존 회귀, 빌드, 브라우저 테스트를 깨끗한 환경에서 수행한다. 패치가 동일해도 검사 대상 SHA가 달라지면 재검사한다. 정상 기능의 변화, 미측정 조건, 재현 자료를 PR에 기록한다. 프로젝트가 지정한 다중 파일 기능·재현 버그는 경계에서 독립 리뷰 1회를 거친다. 파일럿의 자동화 종점은 검토 가능한 PR이다.
5. **학습.** 결과 기록에는 실패 유형(요구 오해·테스트 선택·구현·인프라), 관찰 근거, 다음 가설을 남긴다. 같은 실패가 반복되면 에이전트 지침 후보로 올린다. 예컨대 ‘임시 화면의 데이터를 원장 값으로 오인’하는 실패에는 ‘연결 실패 경로에서 화면과 요청 횟수를 함께 확인’한다는 후보를 만들 수 있다. 후보는 채택 전까지 제품 작업의 기본값에 영향을 주지 않는다.

## 에이전트가 다음 세대로 넘어가는 조건

- **버전.** 현행 지침 A와 A에서 한 가지를 바꾼 후보 B를 해시로 고정한다. 각 실행은 부모 버전, 앱 기준 SHA, 평가 세트 버전, 요청 모델/effort, 확인 가능한 반환 모델/effort, 도구 버전·예산을 남긴다. 첫 작업자 제안은 로컬 모델 라우터의 `astra → gpt-6.2-astra`다. 양쪽 배정이 같아야 비교 가능하며 모델 식별 불가·변경은 보류한다. 반환 effort가 노출되지 않으면 요청 설정과 분리해 ‘미측정’으로 기록한다.
- **시험 분리.** 공개 과거 사례는 개발용이다. 판정자는 미공개 입력·기대값을 작업자와 분리해 보관한다. 같은 원인·패치 계열이 양쪽에 섞이지 않게 기능군 단위로 분할한다. 평가 작업자는 문제와 기준 상태만 받고, 정답 패치·해결 이후 Git 이력·평가 저장소에는 접근할 수 없다. 채점은 패치 제출 후 별도 환경에서 한다. 공개 저장소에는 집계와 세트 해시만 남긴다. 세부 오답을 개발에 공개한 과제는 보류 세트에서 은퇴시킨다.
- **비교 설계안.** 비용을 볼 수 있는 작은 실험으로 시작한다. 미공개 6과제(오류 2, 저위험 기능 2, 올바른 무변경 2)를 각 버전이 과제당 독립 2회 수행한다. 최대 24시행이다. 작업 순서는 교차하고 초기 상태·권한·도구·한도는 동일하게 맞춘다. 첫 시도 해결 수/6, 두 번 모두 성공한 과제 수/6, 과제별 승·무·패, 시간·호출·토큰을 나란히 기록한다. 청구액을 관측할 수 없으면 미측정으로 둔다.
- **채택 규칙 제안.** 금지 동작·기존 회귀·오류를 숨기는 테스트 약화는 1건이라도 기각한다. 나머지는 과제별 성공 횟수가 A보다 줄어든 과제 0개, 두 번 모두 성공한 과제가 최소 1개 순증하고 총 호출·시간이 사전 예산 이내일 때만 제한 적용 후보가 된다. 동률은 A 유지, 환경·대상 모델·채점 문제는 보류다. 여섯 과제로 일반 성능 향상을 단정하지 않는다. 다음 저위험 작업 3건에서 독립 검사를 거친 뒤 유지 여부를 결정하고, 반복 사용으로 노출된 보류 세트는 교체한다.
- **복구.** 작업자 기본 버전은 단일 Git 참조로 관리한다. 제한 적용 중 보호 위반 또는 확인된 회귀가 발생하면 새 작업 배정을 멈추고 부모 참조로 되돌린다. 진행 중 실행은 버전을 고정한 채 격리 종료한다. 이미 통합한 제품 변경은 영향이 확인된 개별 PR을 revert한다. 실패 기록과 이전 버전은 다음 비교에 보존한다.

변경 가능 경로는 이슈마다 제어기가 고정한다. 주문·취소 전송, 전략 기동, 위험 한도 집행, 승인 계약, 원장 스키마, 자격 연결에 걸친 발견은 증거와 제안만 남겨 별도 작업으로 넘긴다. 평가 세트·채점기, CI·권한, 의존성 설치 스크립트, 전역 스킬, 모델 배정은 후보의 쓰기 범위 밖이다. 경로와 diff를 검사한 뒤 실제 실행은 격리한다. 비공개 평가값은 별도 판정 프로세스에서 앱의 공개 인터페이스에 입력하고 응답·상태를 대조한다.

실행 기록 한 건에는 이슈, 기능과 기대 행동, 기준/패치/지침/검사 해시, 모의·격리 등 환경, 실제 관찰과 실패 분류, 모델 사용량, 결과 링크를 담는다. 상태는 대기 → 실행 → 판정 → PR 또는 기각·보류다. 재시작 시 결과가 이미 있으면 재사용하고, 중단된 시도는 이유와 사용한 예산을 남긴다. 비밀·계좌번호·원본 모델 대화는 공개 기록에서 제외한다.

가짜 브로커·로컬 브라우저만 허용하고 호스트 네트워크·운영 4303/4304·원장·승인 파일 접근을 격리 계층에서 차단한다. 모델 호출은 제어기의 승인된 모델 연결로 중계한다. 런타임 의존성은 기준 lockfile로 별도 준비한다. `scripts/dev.ts`의 자동 비밀 주입과 `vts:test` 실행 경로는 자동화 대상에서 제외한다. 작업본과 지침만으로는 이 격리가 성립하지 않는다. [프로젝트 실행 진입점](../../package.json) · [개발 서버](../../scripts/dev.ts)

파일럿 제안 한도는 동시 작업 1개, 제품 후보 1개, 작업자 시행당 10분·모델 호출 8회다. 메타 비교는 최대 24시행(작업자 합계 240분·192호출)이며 CI·평가 시간과 사용량은 별도로 집계한다. 유료 API를 쓰는 경우 선확정 지출 한도 내에서만 배정한다. 시간 초과·모델 할당량·격리 실패·금지 접근은 중단 사유다. 인프라 실패의 재시도는 원인 확인 후 같은 키의 새 시도 1회만 같은 예산에 포함한다. 결과 불명인 쓰기/게시 동작은 외부 상태를 먼저 대조한다. 주기 실행은 파일럿 이후 별도 운영 결정이다.

## 파일럿 이후의 상시 운영안

세 단계가 검증되면 merge된 변경은 영향받은 기능 검사, 새로 채택된 이슈는 제품 개선 작업, 같은 원인의 반복 실패는 지침 후보 생성 이벤트로 연결한다. 제어기는 같은 원인의 열린 이슈·PR을 재사용한다. 에이전트가 만든 PR의 CI 이벤트는 그 PR의 검증으로만 소비해 작업이 스스로 증식하는 것을 막는다. 이벤트가 없는 기능은 별도로 허용한 주기에 마지막 검증 시각이 오래된 순서로 탐색한다. 제품 개선이 없던 주기도 유효한 결과다.

새 기능은 사용자가 미리 정한 목표·허용 화면·수용 기준 안에서 제안부터 구현 PR까지 이어갈 수 있다. 범위를 벗어난 기능은 제안 목록에 남긴다. 운영자는 주기별로 **증거가 있는 요구 동작 수/전체**, **기존 재현 오류 중 수정 후 통과한 수/재현한 수**, **채택 기능 중 수용 검사를 통과한 수/착수한 수**, **다시 열린 회귀 건수**를 본다. 분모가 0이면 해당 없음, 관측이 없으면 미측정이다. 지침 버전의 효과는 별도 비교 결과로만 집계한다.
