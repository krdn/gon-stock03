# KIS 트레이딩 웹앱 조사

확인: 2026-11-14. 목적은 국내 주식·ETF를 개인 PC에서 수동·전략 모의매매하는 웹앱이다. 전체 화면을 먼저 만들고 기능을 연결한다는 사용자 요청을 따른다.

화면별 상세 명세와 출처는 앱의 `/design`에서 탐색한다. 레지스트리는 [src/specs.ts](../../src/specs.ts), 기술 결정은 [architecture/workbench.md](../architecture/workbench.md), 실행 상태는 [STATE](../STATE.md)가 기준이다.

위 판단은 이 프로젝트의 설계다. 공식 샘플 자체를 운영·동시성·복구 검증이 완료된 거래 엔진으로 취급하지 않았다.

## 필요한 화면

매일의 흐름은 `대시보드 → 시장/관심종목 → 트레이딩 → 주문·체결 → 포트폴리오 → 일지`다. 전략 연구는 `전략 정의 → 백테스트 → 자동 데모 재생 → 이벤트 검토`로 분리했다. 위험관리·알림·데이터 상태·연결설정은 이 흐름을 지원한다. KIS 모의 매매는 실제 API 데이터를 별도로 보여주며 설계실은 화면·계약·근거·개발 단계를 연결한다. 총 15개 화면의 입력·계산·실패·수용 기준은 `/design?tab=screens`에서 볼 수 있다.

## 확인 범위와 다음 조사

실제 모의 인증·잔고·현재가·일봉·당일 주문 조회는 [검증 기록](../verification/2026-11-14.md)에 있다. 실제 KIS 주문 전송·부분체결·정정취소·장중 WebSocket·거래일·수수료/세금·시세 권리·전체 종목 마스터는 아직 검증하지 않았다. 해외·선물옵션·신용·실전·다중 사용자는 현재 범위 밖이다. 코드와 합성 테스트만으로 KIS 연속 자동매매 운영이 검증됐다고 표현하지 않는다.

독립 리뷰 후 [공식 잔고 필드 매핑](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_balance/chk_inquire_balance.py)을 재확인했다. 예수금(`dnca_tot_amt`)과 총평가금액(`tot_evlu_amt`)을 분리하고 손실 기준에는 후자를 사용한다. 실제 매수·매도 결제 전후 평가액 대조는 미검증이다.
