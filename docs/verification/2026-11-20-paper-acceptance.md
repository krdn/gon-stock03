# 개인 PC용 KIS 모의 버전 최종 수용

**판정은 예외 1건을 포함한 수용이다.** 실제 KIS 모의계좌에서 한 원주문의 일부 체결 후 잔량 취소를 제출하고 그 결말까지 확인하는 장면은 미관측이다. 11월 20일 사용자가 변경과 허용에 관한 판단을 위임했고, 이번 모의 버전에서는 이 장면을 필수 종결 조건에서 제외했다. 제품 기준은 `a1dcfee`이며 이 수용 작업은 테스트와 문서만 변경한다. [사전 기록한 판정 기준](https://github.com/krdn/gon-stock03/issues/25#issuecomment-7027600289)

## 실제 KIS에서 확인한 범위

|---|---|
| 11월 16일 삼성전자 1주 | 미체결 1주인 상태에서 한정 API 취소를 1회 제출했다. 접수 응답 뒤 REST에서 취소 상태·잔량 0주를 확인했다. [주문·취소·대조](2026-11-16-samsung-paper-run.md) |

## 격리 검증

브로커 응답만 테스트 전송기로 공급했다. 제품 HTTP 서버에서 단가 상한 80,000원으로 KODEX 200 두 주를 주문하고, 같은 원주문의 체결 1주·잔량 1주를 조회했다. 실제 화면과 동일한 잔량 취소 요청(`reconcileFirst: true`)을 보낸 뒤 REST 대조를 다시 수행했다. 아래 수량과 POST 횟수는 각 독립 테스트의 값이다. [재실행 가능한 검사](../../tests/paper.test.ts)

| 대조 시점에 발생한 일 | 취소 POST | 최종 체결 / 취소확인 / 잔량 |
|---|---:|---|
| 잔량 1주 취소 접수 및 확인 | 1 | 1 / 1 / 0 |
| 전송 전 재조회에서 전량 체결 | 0 | 2 / 0 / 0 |
| 취소 요청 거절 후 전량 체결 확인 | 1 | 2 / 0 / 0 |

각 경우 최초 매수 POST는 1회였다. 취소를 보낸 경우 접수 또는 거절 응답 직후 원장의 불명 상태를 확인했다. 최종 대조 뒤 취소를 다시 요청하거나 같은 매수 요청을 반복해도 추가 전송은 0회였다. 최초 테스트에서 접수와 재조회 응답의 주문번호 앞자리 0 표기 차이로 두 단정이 실패했다. 두 번호의 수치 동일성과 취소 전문이 재조회한 원주문번호·지점 값을 정확히 사용함을 각각 확인하도록 고쳤다.

## 적용 경계

이 판정은 국내 주식·ETF 개인 PC 모의 버전에 적용한다. #3의 15개 하위 화면과 #2의 4개 공통 하위 작업은 완료됐다. 화면 수용은 당시 제시된 상태·배치·동적 장면에 한정한다. 실제 장애 복구·전략 주문 증거와 함께 상위 #1을 인수한다. [화면 수용](2026-11-19-issue-closeout.md) · [응답 유실과 원주문 복구](2026-11-18-live-transitions.md) · [정상 전략 주문](2026-11-19-strategy.md)

한정 원주문의 기존 허용 조건과 중복 전송 차단을 유지한다. 일반 취소 지원을 확대하려면 KIS가 지원하는 취소가능수량 확인 절차와 해당 범위에서의 실제 경합 증거를 다시 검토한다. 공식 문서에는 취소 전 가능수량 조회가 필요하며 그 조회의 모의 TR은 미지원으로 표시된다. 이번 판정에서 새 주문·취소·전략 전송 또는 예약은 0회다. [KIS 정정취소 규격](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/order_rvsecncl/order_rvsecncl.py) · [가능수량 조회 규격](https://apiportal.koreainvestment.com/api/apis/public/detail?accessUrl=/uapi/domestic-stock/v1/trading/inquire-psbl-rvsecncl)

## 검증 결과

신규 HTTP 시나리오 3개, 전체 단위·서버 274건, 브라우저 177건, 타입 검사·프로덕션 빌드가 통과했다. 독립 읽기 전용 검토에서 Gemini 4 Argon/high는 테스트와 예외를 포함한 수용 문서에 PASS를 반환했다. 요청과 CLI 초기화 모델은 `gemini-4-argon-high`, 최종 상태는 SUCCESS였다. 공급자 내부 모델·effort는 별도 미측정이다. 리뷰 문구 중 11월 19일 취소 미제출에 관해서는 앱에서 보낸 API 요청 0회만 입증됐다. 사용자의 모바일 제출 여부는 미확인이다.
