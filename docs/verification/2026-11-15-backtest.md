# #21 저장 일봉 백테스트 검증

저장 일봉을 선택하고 입력·결과를 보존하는 구현 검증이다. 실제 KIS 일봉 수집·공식 달력 대조·수익성·장중 실행의 성공 증거는 아니다.

- 기준: `f50e08040dc883f5577579221cea433d3054c40e`. #7·#15 native completed, 통합 커밋의 main 포함, #21 Ready 및 `gon-workflow ready`를 착수 전에 확인했다.
- 제품 대상 SHA: 커밋 후 고정한다. PR·최종 CI는 이후 기록한다.
- 사용자 수용: 사용자는 이 세션에서 #21 구현·지정 검증·PR 인계를 진행하도록 지시했다. #21 화면에 대한 직접 육안 수용 답변·통합은 아직 없다. 이전 #15 수용 판단을 재사용하지 않는다.

## 입력과 계산

`POST /api/backtest/daily`는 C02의 수집 ID·출처·종목·수정주가 정책과 선택 기간을 확인한다. 구간 수집 완료·입력 달력 대조 통과가 필요하며 선택 기간 거래일과 저장 봉을 다시 비교한다. 누락·중복·잘못된 정책·0 가격/거래량·표본 부족은 거부한다. 달력 URL의 진위를 인증하지 않는다.

기간 안의 종가만 이동평균에 넣는다. 이전 기간의 준비 봉과 이후 기간의 가격은 계산에 넣지 않는다. 교차 신호를 다음 봉 시가에 실행하고 매수 슬리피지는 더하고 매도 슬리피지는 뺀다. 비용은 매 체결금액 × bp / 10,000의 원 단위 올림이다. 평가자산은 현금 + 수량 × 종가이며 낙폭은 초기자금 포함 최고 평가자산 대비 하락률이다. 마지막 보유분은 강제 청산하지 않는다.

SQLite `backtest_experiments`에 선택 봉·설정·수집 메타데이터·입력 달력·엔진 버전·SHA256·결과를 저장한다. SHA256은 계산 입력과 출처 기록의 동일성을 확인하며 가격 진위나 원천 자료의 PIT를 보증하지 않는다. 원래 수집 기록이 바뀌어도 재현은 고정 스냅샷만 사용한다. 같은 스냅샷은 하나의 실험으로 반환하고 기존 실험을 덮어쓰지 않는다. 재계산 결과가 달라지면 불일치로 표시한다.

예시 fixture에서 단기2/장기4, 자금100,000원, 수수료10bp, 슬리피지5bp를 쓴다. 2026-01-12 종가 신호는 01-13 시가20에 슬리피지를 더한 20.01로 4,992주를 매수하고 수수료100원을 차감한다. 이 숫자는 테스트 시나리오이며 시장 관측·성과가 아니다.

세금·배당·기업행사·호가단위·가격제한·유동성·미체결은 계산하지 않는다. 원주가의 분할·병합과 수집 시점 수정주가의 사후 조정은 성과 해석을 왜곡할 수 있다. 화면에 이 가정을 표시한다. 실제 거래 가능성이나 이익을 주장하지 않는다.

## 공식 출처와 미검증

[KIS 공식 일봉 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_daily_itemchartprice/inquire_daily_itemchartprice.py)에서 최대100건, J=KRX, D=일봉, 0=수정주가/1=원주가를 2026-11-15 확인했다. 새 수집기를 만들지 않고 기존 C02 저장 계약을 사용했다. [Node SQLite 문서](https://nodejs.org/api/sqlite.html)는 파일 DB·바인딩 참조다. v24 전용 문서는 도구 접근 실패였으므로 실제 Node24 저장·재시작 테스트를 근거로 삼는다.

실제 KIS 기간별 일봉·공식 달력 대조, 사용자 직접 육안·장중 수용, 실제 주문·취소·불명 복구·연속전략은 미검증이다. #7 공개 마스터3962 실조회와 혼동하지 않는다. C04 WebSocket·V01 장중 통합은 별도다. STE 기준 파일·graphify 부재, #8 Fable 한도 오류와 기술스택 추천 문서의 범위를 유지한다.
