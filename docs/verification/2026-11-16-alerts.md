# #17 알림·이벤트 검증

[이슈 #17](https://github.com/krdn/gon-stock03/issues/17)의 KIS 감사·연결/차단 이벤트와 읽음 영속화를 검사했다. 실제 KIS 업무 API·주문·취소·예약·외부 메시지 발송은 실행하지 않았다.

- HTTP 회귀2건 RED 확인: KIS 감사 이벤트 부재, 연결 실패/취소 차단 이벤트 부재. 구현 후 통과.
- `npm test`: 단위/API134건 PASS. 새6건은 감사 ID 반복 조회, 읽음 SQLite 재시작 보존, 저장 실패 원자적 롤백, 새 감사 미읽음, 연결 실패→복구 전환·중복 억제·원문/계좌값 비노출을 확인한다.
- `npm run build`: TypeScript 및 빌드 PASS. 기존 번들500kB 경고 유지.
- 전체 브라우저76건 PASS. 새3건은 환경/요청 ID/원인 링크·중요도 필터·폴링·모바일과 읽음 저장 실패/새로고침 보존을 검증한다. 실제 화면 확인에서 상단 혼합 환경 표기 누락을 RED 재현해 수정했다.
- 초기 저장 재시작 테스트는 닫힌 HTTP keepalive 연결 재사용으로 실패했다. 조회에 Connection: close를 써 재시작 검증을 안정화했다. 연결 이벤트 수 검사는 기존 DEMO 초기 이벤트를 제외하도록 KIS 환경을 명시했다.
- `agent-browser`로 메모리 DB에 예시 감사 이력을 넣고 1440×1050·390×844 화면과 모두 읽음 동작을 확인했다. 실제 주문·복구 증거가 아니다. 검사 서버·브라우저를 종료했다.

[PC 예시](assets/alerts/desktop.png) · [좁은 화면 예시](assets/alerts/mobile.png). 최종 혼합 환경 표기와 감사 예시 이력을 보여준다.

원본 `paper_audit`는 수정하지 않는다. 새 읽음 테이블은 감사 ID만 저장한다. 알림에는 상태·행동·내부 요청 UUID만 투영하며 evidence, brokerId, organization, 잔고를 복사하지 않는다. 기존 accepted/unknown/rejected KIS 요약은 감사 투영과 중복되므로 알림에서 제외하고 원본 workspace JSON은 보존한다. 감사 도입 전 요약도 원본에 보존하지만 알림 화면의 KIS 이력 기준은 감사 원장이다. 같은 감사 재조회는 동일 ID이며, 별도 조회/복구 시도는 별도 감사 이력이다. 최근1000건만 화면에 제공하고 원본 감사는 유지한다.

공식 참고: [React 목록 키](https://react.dev/learn/rendering-lists). DB의 안정된 ID를 렌더 키로 사용한다.

독립 리뷰·원격 CI·사용자 화면 수용은 작업 파일에서 상태를 확인한다. WebSocket 이벤트는 #19, 실제 장중 통합 수용은 #25의 미검증 범위다.


원 리뷰는 실제 `claude-opus-5-5`/요청 high로 P2 7건을 제시했다. 반복 대조 성공 기록, 관측 ID만 읽음 저장, 이전 요약 이중 표시 방지, 실패 요청의 오류 분류 고정, 이전 상태 미기록 문구, WebSocket 범위 구분, 한정 취소/잘못된 취소 입력 차단 기록을 보완했다. 6개 회귀 검사와 화면 환경 표기 검사에서 RED→GREEN을 확인했다. 원 리뷰의 revision 우려는 App의 `<` 비교와 동일 revision 새 감사 브라우저 회귀로 확인했다. P0/P1 지적은 없었다.

`git diff --check`와 문서 상대 링크 검사 PASS. STE strict는 기준파일 `docs/conventions/ste100-writing.md` 부재 exit2로 미검증이다. 수정분 리뷰와 원격 CI는 작업 파일에 기록한다.


[원 리뷰](assets/alerts/review.json) · [수정분 리뷰](assets/alerts/review-followup.json). 두 응답의 modelUsage는 `claude-opus-5-5`, 요청 effort는 high다. 서버 내부 effort는 독립 확인하지 않았다. 수정분 리뷰는 P2 7건 해소를 확인했고, 로컬 JSON 오류를 외부 서버 오류로 분류하는 경미1건을 남겼다. 이를 RED 재현하고 분류 미확인으로 고쳐 최종 단위/API134건과 빌드를 재검증했다. 마지막 수정의 외부 추가 검토는 반복하지 않았다.

기존 main의 KIS 요약 record 호출은 submit 결과의 accepted/unknown/rejected 한 곳뿐이었다. cancelProbe의 전송 후 오류는 unknown 메시지로 저장·반환하고, 저장 오류는 HTTP에서 먼저500 처리하므로 전송 실패를 사전 차단으로 기록하지 않는다. 감사 JSON 조회 비용과 동일 상태 조회의 workspace 재기록 비용은 별도 최적화 대상으로 남기며 이번 완료 조건과 분리한다.
