# #12 트레이딩 검증

[이슈 #12](https://github.com/krdn/gon-stock03/issues/12)의 DEMO 확인·접수 경계를 검사했다. 실제 KIS 업무 API·주문·취소·예약을 실행하지 않았다.

- 초기 회귀 3건 실패: 확인 후 시세 변경에도 접수 가능, 예약 제외 매도량 표시 없음, 응답 손실 후 신규 요청 차단 없음. 구현 후 3건 통과.
- `npm test`: 단위/API 128건 통과. 기존 `tests/engine.test.ts`에서 현금·매도 예약·위험 한도·멱등성·접수와 다음 봉 체결 분리를 확인한다.
- `npm run build`: TypeScript 및 빌드 통과. 기존 500kB 번들 경고 유지.
- `npx playwright test --reporter=list`: 최종 전체 80건 통과(47.0초). 새 7건은 시세 재확인·정지/연결 차단·예약 매도량·종목 전달·응답 손실/새로고침 대조·동일 요청 재시도·명확한 거부 후 편집을 검증한다.
- 첫 전체 검사 76/78: 기존 2건은 비활성 버튼 클릭과 닫힌 확인창 재시도를 기대했다. 새 차단/동일 요청 재시도 계약으로 수정하고 오류 문구·비밀값 비노출·POST0 검증을 유지했다.
- `agent-browser`로 격리한 메모리 DB·비밀값 미주입 서버에서 1440×1050과 390×844를 확인했다. DEMO 1주 접수 결과는 미체결로 표시됐다. 브라우저와 검사 서버는 종료했다.
- `git diff --check`, 작업 문서 상대 링크 검사 통과. STE strict는 `docs/conventions/ste100-writing.md` 부재로 exit2, 미검증이다.

[PC 화면](assets/trading/desktop.png) · [좁은 화면 확인창](assets/trading/mobile-confirm.png) · [접수 결과](assets/trading/mobile-result.png).

응답 손실 요청은 같은 브라우저 탭의 sessionStorage에 보존한다. 새 탭·브라우저 데이터 삭제까지 포괄하는 전역 불명 원장이 아니다. KIS 원장 복구와 일반 웹 취소409는 기존 별도 계약을 유지한다. 사용자 직접 화면 수용 및 #25 장중 통합 실증은 미검증이다.

공식 참고: [React useRef](https://react.dev/reference/react/useRef)의 이벤트 핸들러 내 가변 ref를 동기 중복 클릭 잠금에 사용했다. 표시 상태는 React state로 관리한다.

독립 리뷰: 중앙 설정과 dry-run은 Claude `claude-opus-5-5` / `high`. [원 리뷰](assets/trading/review.json)의 실제 modelUsage도 `claude-opus-5-5`다. 서버 내부 effort 독립 확인은 하지 못했다.

원 리뷰 P2 두 건을 재현했다. 전송 전 freshness 검사 거부를 definitive로 표시해 pending 기록을 해제하고, 재시도는 현재 합성 시세를 명시적으로 확인해야 활성화되며 시세가 바뀌면 다시 비활성화한다. 수정 후 관련 브라우저18건 통과. [수정분 리뷰](assets/trading/review-followup.json)는 두 원 지적 해소와 P2 재시도 회귀 1건을 제시했다. 재시도 중 전송 전 거절이 원래 불명 요청을 지우는 경우다. 이를 RED 재현한 뒤 `notSent`와 재시도 여부를 구분해 원래 요청을 보존했다. 마지막 수정은 직접 회귀 검증하며 외부 추가 PASS로 표시하지 않는다. P0/P1 지적은 두 리뷰 모두 없었다. 최종 전체80건 통과로 마지막 회귀를 검증했다. 원격 PR/CI는 작업 파일에 연결한다.
