## 실제 연결

2026-11-15 13:31:48 KST, Infisical CLI 0.45.7의 기존 인증으로 `dev /kis`를 주입했다. 필수 변수4개 존재를 값 출력 없이 확인했다. 변경된 `KisClient`의 모의 인증과 잔고 조회에서 다음 요약만 수집했다.

```json
{"injection":"present","authentication":"ready","balance":"ready","connected":true,"complete":true,"pages":1,"checkedAt":"2026-11-15T04:31:48.798Z","failure":null}
```

최종 수정 코드에서도 13:42:09 KST 인증·잔고1페이지 전체 조회를 확인했다. 같은 주입 환경의 두 독립 클라이언트로 발급을 시도하자 첫 tokenP는 HTTP200, 두 번째는 HTTP403/`EGW00133`이었다. 수정 전 permission 오분류를 확인했고 수정 후 `failure.kind=rate-limit`, 잔고 미조회·성공 없음으로 확인했다. 공개 오류 목록에는 이 코드가 없으므로 이 분류의 근거는 실제 모의 tokenP 응답이다. 요청은 모의 호스트의 tokenP 2회와 inquire-balance 1회에 한정했다.

실행한 주입 접두 명령은 `infisical secrets-manager run --env dev --path /kis --silent -- node --import tsx`다. 뒤의 검사 코드는 상태·시각·오류 종류만 출력했다. 사용자 안내의 `npm run dev`도 같은 환경·경로를 사용한다.

모의 조회 성공은 주문·체결·취소·연속 전략·장중 수용 증거가 아니다. 실제 만료·권한거부·네트워크 장애는 유발하지 않았다. 해당 실패 분기와 연속 페이지는 대체 HTTP 응답으로 검증했다. KIS의 [인증·잔고 공식 샘플](https://github.com/koreainvestment/open-trading-api), [공식 오류코드](https://apiportal.koreainvestment.com/faq-error-code), [Infisical 설정](https://infisical.com/docs/cli/project-config)을 확인했다. 상세 출처는 `docs/start-context.json`의 #8 맥락에 있다.
