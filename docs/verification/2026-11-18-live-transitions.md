검증기가 실제 KIS 모의 주문의 HTTP 응답을 받은 뒤 제품에 전달하기 전에 끊었다. [실험 승인](https://github.com/krdn/gon-stock03/issues/25#issuecomment-6970322750) · [합산 한도](https://github.com/krdn/gon-stock03/issues/25#issuecomment-6970358496). 14:48 최초 검사는 지정가 193,400원과 재조회 193,300원의 불일치로 원주문 전송 0회였다. 별도 합산 승인에서는 사전검사 최대 3회 중 첫 회에 실제 주문을 보냈고 이후 시도하지 않았다.

## 전략 전송 지연 측정

14:52 이후 별도 읽기 전용 프로세스에서 제품의 1,100ms 요청 간격을 유지하고 잔고·당일 주문·현재가·매수가능 조회를 순차 수행했다. 시작 전 1.3초 쉬고 각 측정의 시작부터 다음 요청을 보낼 수 있는 가장 이른 시점까지 7.528초, 5.086초, 7.162초가 걸렸다. 모두 신호 시세의 5초 유효시간을 초과했다. 이 수치는 후속 측정이며 14:43 두 주문의 개별 네트워크 지연 원인을 특정하지 않는다.

종료된 전용 원장 3개를 읽기 전용으로 열어 SQLite 무결성 검사(`quick_check`) 결과가 모두 `ok`임을 확인했다. 같은 요청별 감사 기록은 시장가 실행의 sending→accepted→filled, 유실 실험의 sending→unknown→recovery-inspect→recovery-confirm(filled) 순서다. 11월 12·13·16·17·18일의 모의 당일 주문내역도 읽기 전용으로 대조했다. 날짜별 0·0·5·0·3건이며 총 8건 모두 수량 1주였다. 이 범위에서는 부분체결·잔량 취소 실증으로 재사용할 행이 없다.

지정 Argon/high에 마스킹 기록과 PNG 8개를 제공했다. CLI init 모델은 `gemini-4-argon-high`, 요청 effort는 high였고 실제 응답은 SUCCESS·PASS였다. 검토자가 화면에서 직접 확인한 전략 신호는 매수 차단 한 장면이다. 서버 내부 모델·effort는 독립 검증하지 못했다. 후속 조건부 계약은 이 판정 범위 밖이다.
