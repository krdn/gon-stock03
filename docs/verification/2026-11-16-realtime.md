# #19 실시간 기반 검증

실제 KIS 연결 없이 모의 실시간 수신·재연결·REST 대조 안전장치를 구현했다. #19 수용·통합과 #22/#25 해제는 아직 하지 않는다.

## 공식 계약과 구현 선택

2026-11-16에 KIS 공식 저장소 [74b0a08](https://github.com/koreainvestment/open-trading-api/tree/74b0a082fa67a0be5bf53f561719c853890ed2df)을 조회했다. 내려받은 main과 고정 커밋의 세 파일 바이트가 일치했다.

- [실시간 함수](https://github.com/koreainvestment/open-trading-api/blob/74b0a082fa67a0be5bf53f561719c853890ed2df/examples_user/domestic_stock/domestic_stock_functions_ws.py): 모의 시세 `H0STCNT0`, 체결통보 `H0STCNI9`, 47/26 필드. 시세 거래일·시각·누적거래량을 확인한다.
- [인증·수신 예제](https://github.com/koreainvestment/open-trading-api/blob/74b0a082fa67a0be5bf53f561719c853890ed2df/examples_user/kis_auth.py): 승인키 헤더, AES256-CBC/PKCS7, PINGPONG에 pong. [주소 설정](https://github.com/koreainvestment/open-trading-api/blob/74b0a082fa67a0be5bf53f561719c853890ed2df/kis_devlp.yaml): 모의 포트31000. 실전 포트와 실전 체결TR은 사용하지 않는다.
- [KRX 거래시간](https://global.krx.co.kr/contents/GLB/06/0602/0602020204/GLB0602020204T1.jsp): 검색 도구가 반환한 공식 본문에서 정규장09:00–15:30과 휴장 예외를 확인했다. 직접 open은403. 특정 거래일의 개장을 확인한 증거가 아니다.
- 포털 공개 상세 요청 `accessUrl=H0STCNT0/H0STCNI0`은500이었다. 미지원 판정 근거가 아니며, 공식 예제를 근거로 구현했다. 실제 서버의 필드 변동은 계약 오류로 중단한다.

체결통보 수량을 직접 더하면 중복·역전 통보로 원장이 틀릴 수 있다. 통보는 대조 필요 상태만 만들고 기존 `PaperBroker.refresh(true)`가 잔고·주문을 확인한다. 예: 체결1주 통보가 두 번 와도 원장은 자동 합산하지 않으며 REST의 누적체결1주와 대조한다. 대조 중 새 통보·끊김·불명 주문이 있으면 완료로 표시하지 않는다.

`server/realtime.ts`가 구독·복호화·시세 검증·제한된 재연결을 맡는다. 첫 시작과 재연결마다 구독 ACK 두 건, 명시적 REST 대조, 5초 이내 시세가 필요하다. 누적거래량 중복/역전·이전 시각·미래/다른 거래일 입력을 제외한다. 끊김은1/2/4초로 최대3회 재연결하며 대조·전략을 자동 재개하지 않는다. 수신45초 초과·장외·긴급정지는 연결을 닫는다.

주문 직전에도 세션 세대·대조 버전·시세 유효시간을 재검사한다. 시작 이력은 SQLite에 영구 저장하므로 재시작·별도 `PaperBroker`에서도 대조 없이 주문할 수 없다. `submitSignal`은 기존 `signal`과 `PaperBroker.submit`을 사용한다. 연속전략 스케줄·활성화는 #22 범위이며 여기서 자동 실행하지 않는다. DEMO 재생과 가격은 별도로 유지한다.

## 설정과 실행 경계

승인키와 체결 구독 HTS ID는 Infisical 서버 환경변수 `KIS_WS_APPROVAL_KEY`, `KIS_HTS_ID`로 주입한다. 자동 승인키 발급이나 인증 실행은 추가하지 않았다. AES key/iv는 구독 응답에서만 받으며 API/이벤트에 노출하지 않는다.

`KIS_WS_SESSION`은 운영자가 공식 당일 개장·특별시간을 확인한 뒤 주입하는 JSON이다. 필드는 `date`(YYYY-MM-DD), `open`/`close`(HH:MM), `verified:true`다. 누락·다른 날짜·주말·장외는 시작을 거부한다. 자동 휴장 달력 인증은 없으며, 이 설정의 존재만으로 공식 확인 사실을 증명하지 않는다. 시간 범위는09:00–15:30 안으로만 좁힐 수 있다.

모의 화면의 명시적 시작·정지·대조는 `POST /api/kis/realtime/start|stop|reconcile`을 사용한다. GET 상태/원장과 화면 이동은 KIS 호출을 하지 않는다. 한 번 시작한 DB는 수신 정지 후에도 신규 주문 차단을 유지한다. 이전 버전에는 이 안전장치가 없으므로 사용한 DB를 구버전으로 재실행하는 롤백은 허용된 복구 절차가 아니다.

기존 고정 승인·1회 제한·120초·웹 정정취소409를 보존했다. 이번 실행에서는 승인키·HTS ID를 주입하거나 실제 수신/인증/주문/취소/예약/외부알림을 실행하지 않았다. .local 원장과 다른 worktree는 사용하지 않았다.

## 독립 리뷰 결과와 남은 조건

중앙 `review-models.json`·`review-llm --dry-run`은 기본 Claude Opus5.5/high였으므로 사용하지 않았다. 사용자 지정 대안 `gemini-4-argon-high`를 `agy models`에서 확인했다. `--model gemini-4-argon-high --effort high --output-format stream-json --print=...`로 비밀값 없는 변경·관련 코드·테스트를 전달했다.

요청 모델과 `init.model=gemini-4-argon-high`는 일치했다. 세션 `b886694f-9dd2-479e-8ddd-05771a941a9c`는240초 후 exit3, `result.status=ERROR`, `finished_reason=print_timeout`으로 종료했다. 응답 본문은 비어 있다. **독립 리뷰 미완료이며 PASS가 아니다.** 관측한 스트림에 도구 실행은 없었다. CLI의 plan 옵션 무효 경고도 확인했다. 제공 텍스트 외 도구 사용·수정은 금지하는 프롬프트를 전달했다.

서버 내부 모델·effort는 독립 확인하지 못했다. 다른 모델로 대체하거나 추론 강도를 높이지 않았다. 로컬 회귀와 변경 검사를 마쳤으나 독립 검토를 대체하지 않는다. 지정 모델의 최종 검토 결과 확보·지적 처리, 사용자 수용·통합 전까지 #19는 미완료이고 #22/#25는 Blocked다.

`evolve docs ste-lint --strict --changed refs/remotes/origin/main --added`는 `docs/conventions/ste100-writing.md` 부재로 exit2였다. 수정 문서의 상대 링크 존재와 `git diff --check`는 통과했다. 기존 미추적 `graphify-out/`를 보존하며 표준 handoff의 제한은 원격 기록에 명시한다.
