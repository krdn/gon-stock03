[검사 해시·관찰값·중복 요청](../verification/129-replay.json). 최초 평가기 초안에서 거래일지 모의 응답 문구가 서버 계약과 달라 대조군이 시간 초과됐다. 실제 저장 오류 문구를 사용하고 앱 기동 전에 가상 시계를 설치해 두 버전을 다시 측정했다. 과거 수정은 제품 개선 건수에서 제외한다.

재생은 Linux에서 기준 lockfile로 격리 준비한 Node 24 의존성(`npm ci --offline --ignore-scripts`)과 Playwright Chromium headless shell 1255를 사용한다. 별도 빈 상태 디렉터리에서 다음 명령을 `before`와 `after`에 각각 실행한다. 같은 키의 동시 요청은 running, 완료 뒤 재요청은 보관한 결과를 돌려준다. 실행 중에는 소유 호스트·PID·시작 시각을 반환한다. 종료된 인프라 오류만 원인 확인 후 같은 키에 `--retry-reason "원인과 조치"`로 한 번 재시도할 수 있다. 재시도 프로세스의 120초 제한에서 첫 시도 경과 시간을 차감한다. 준비와 종료 유예를 포함한 전체 벽시계 시간은 다를 수 있다. 제어기가 비정상 종료해 running이 남으면 이 도구는 그 키를 자동 회수하지 않는다.

```sh
python3 scripts/pilot/replay.py before --state "$PILOT_STATE" --deps "$PILOT_DEPS" --browsers "$PILOT_BROWSERS"
```

평가기는 매회 새 마운트·PID·네트워크 네임스페이스, 빈 환경, 읽기 전용 검사, 메모리 DB와 내부 4314를 사용했다. 호스트 홈·공유 Git 이력·운영 원장·도커 소켓은 평가기 마운트에 없다. 별도 네임스페이스에서 loopback만 있고 외부 경로가 비었으며, 호스트의 4303과 문서용 외부 IP에 연결할 수 없었다. 실제 브로커·운영 계정·장중 화면은 미측정이다.

`node --import tsx scripts/pilot/inventory.ts`는 15화면과 추가 매매 설정·공통 서비스를 포함한 186개 행을 출력했다. 명시적 매핑 104행은 실제 검사 선언 확인 97행·기록 참조만 1행·근거 미연결 6행이다. 나머지 82행은 명세에 대응하는 매핑이 없어 자동으로 추가됐다. 개별 실행 근거가 들어오기 전까지 186행은 미측정이다. `node scripts/pilot/check-inventory.mjs`로 합성 변형을 재현한다. 합성 변경에서 새 화면, 별도 경로, 수용 조건 추가, 없는 제목을 각각 찾아냈다. [검사 연결 및 변형 결과](../verification/129-inventory.json)

첫 작업자 패치는 고정된 TypeScript 7.0.2의 기본 export에서 구 컴파일러 API를 호출해 실패했다. 기존 소유자 종료 확인 뒤 같은 세션의 수정 Dispatch `ctx_005f0832474b`가 Rolldown 파서로 바꿨다. 통합 검증에서 총괄이 TS/TSX 언어 옵션을 명시하고 중첩된 HTTP 검사 대신 이를 포함하는 실제 최상위 검사 제목을 연결했다. 두 Dispatch의 작업자 합계 397.75초, 모델 요청 2회다. SDK 요청·후처리 모델은 gpt-6.2-astra, 요청 effort는 high, 공급자 내부 effort·청구액은 미측정이다. 로컬 모드의 호스트 스킬 탐색이 중첩 네임스페이스에 막혔으며 패치는 제공한 공개 입력으로만 작성했다.

Fable 5.2/high는 추가 크레디트를 요구해 리뷰를 반환하지 않았다. 이후 사용자가 Opus 5.5를 지정해 해당 구독 경로로 리뷰를 수행했다.

## Opus 5.5 독립 리뷰 후 검증

`c941d369`의 외부 리뷰에서 제품 동작 실패의 분류, 시세 요청 계측, 런타임이 다른 캐시 재사용과 인프라 오류 재시도를 보완했다. 두 과거 SHA의 같은 격리 재생에서 예시 행과 시세 요청은 각각 4/4와 0/0이었다. 정상 목록 대조군에서는 두 버전 모두 선택 종목에 대한 실제 브라우저 요청이 관찰됐다. 재생 결과에 각 실행의 런타임·격리 증거와 입력 파일 해시를 저장한다. 커널과 시스템 라이브러리 전체 해시는 미측정이다.

빈 목록 문구를 없애고 쿼리 문자열이 붙은 시세 요청을 추가한 합성 변형은 빈 목록 확인 실패와 요청 건수를 함께 기록해 제품 동작 실패로 분류했다. 별도로 소스 아카이브를 읽지 못하게 한 인프라 실패에서는 원인을 기록한 재시도로 복구했고, 두 번 연속 실패한 키의 세 번째 시도는 차단됐다. 기존 CI의 관심종목 회귀 검사도 표 행 0개와 요청 배열이 비었음을 각각 단언한다.
