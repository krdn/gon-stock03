# #157 브라우저 시차와 공통 상태 만료

[기준 이슈](https://github.com/krdn/gon-stock03/issues/157) · [상위 #149](https://github.com/krdn/gon-stock03/issues/149) · [공통 계약 #6](https://github.com/krdn/gon-stock03/issues/6) · [대시보드 후보 #156](https://github.com/krdn/gon-stock03/pull/156)

브라우저 시계가 서버보다 120초 빠르면 방금 받은 DEMO 상태가 ‘오래됨’으로 보였다. 120초 느리면 이미 만료된 값을 ‘정상’으로 표시하고 행동도 허용했다. [공통 App](../../src/App.tsx)은 이제 서버 관측 시각과 브라우저의 단조 경과 시간으로 표시와 행동 직전 만료를 판단한다.

## 4471 전후 비교

기준 main `04434fd`와 수정본을 같은 Chromium, PC 1440×900·모바일 390×844에서 비교했다. 아래 결과는 두 화면 크기에서 같았다. 정상값은 메모리 DB의 실제 GET, 만료값은 시각을 고정한 예시 응답이다. 일지 POST는 브라우저에서 가로챘다.

| 응답과 브라우저 시계 | 변경 전 표시 / 일지 POST | 변경 후 표시 / 일지 POST |
| --- | --- | --- |
| 방금 성공, 시차 0 또는 −120초 | 정상 / 1회 | 정상 / 1회 |
| 방금 성공, 처음부터 +120초 | 오래됨 / 0회 | 정상 / 1회 |
| 방금 성공, 실행 중 +120초 보정 | 오래됨 / 0회 | 정상 / 1회 |
| 방금 성공, 실행 중 −120초 보정 | 정상 / 1회 | 정상 / 1회 |
| 로컬 성공 10초 전·KIS 성공 60초 전, 시차 −120초 | 둘 다 정상 / 1회 | 둘 다 오래됨 / 0회 |

## 시각 근거와 한계

- [서버 GET](../../server/http.ts)은 요청마다 한 서버 시각을 로컬 observedAt·lastSuccessAt에 기록하고 no-store로 응답한다. [KIS 연결](../../server/kis.ts)은 마지막 전체 성공과 인증 상태를 별도로 확인한다. [공통 계약](../../shared/status.ts)의 `경과 >= staleAfterMs` 경계는 로컬 10초, KIS 잔고 60초다.
- 요청 시작부터의 경과 시간을 포함해 전송 지연만큼 일찍 만료될 수 있다. 같은 성공 시각의 반복 응답은 처음 정한 기한을 연장할 수 없다. HTTP Date가 본문의 관측 시각보다 늦으면 그 차이도 나이에 포함한다. 본문 시각이 응답 헤더의 초 범위를 앞서면 시각을 확정하지 않는다. 사용자에게 보여주는 서버 시각에는 왕복 시간을 더하지 않는다. 늦은 새 응답이 도착해도 이미 지난 인증·취소 기한을 되돌리지 않는다. [High Resolution Time](https://www.w3.org/TR/hr-time-3/) · [HTTP Date](https://www.rfc-editor.org/rfc/rfc9110.html#name-date)
- 실패·시각 역행·복귀 직후에는 새 서버 관측을 기다린다. 이미 교체된 서버의 재등장은 받아들이지 않는다. 동일 인스턴스에서 서버 시계 자체가 뒤로 이동하면 기존 관측 시각을 넘기는 새 응답이나 페이지 재진입이 필요하다. 최초 본문과 헤더가 함께 과거에 고정됐고 이전 관측도 없으면 절대 나이는 판별할 수 없다.
- [전용 Chromium 검사](../../tests/browser/157-app-time.spec.ts)는 열어 둔 화면의 9,999/10,000ms, 59,999/60,000ms, 다시 그리기 직전 행동 차단, 폴링 중단·부분·오류·서버 교체·이전 응답·복귀를 확인한다. 실제 기기의 절전 중 단조시계 정지와 복귀 이벤트가 모두 누락되는 경우는 미측정이다.

## 검토와 인계

- `npm run build`(TypeScript 검사와 Vite 빌드), 4471 Chromium 관련 회귀 40건 통과. 로컬 전체 단위 검사는 275/276으로 고정 검사 포트 4328 충돌(EADDRINUSE) 1건이 발생했다. 전체 검사는 PR Actions에서 확인한다.
- 지정 `gemini-4-neon-high`가 격리된 설계·구현 검토에 응답했다. 첫 구현 호출은 5분 타임아웃이었다. 재검토에서 제기한 시각 결손 뒤의 잔고 복구, 복귀 중 오류 문구, 확인 전 시각 사용을 수정했다. 수정분 검토에서 발견한 ‘로컬 시각 결손과 동시 KIS 부분 실패’도 재현해 수정했다. KIS 자체의 부분·오류 이후에는 새로운 전체 성공을 요구한다. 시간 만료 시 전체 수신 이력은 공통 계약대로 유지한다.

로컬 미리보기는 [4471 예시 일지](http://127.0.0.1:4471/journal)다. 빈 환경의 전용 메모리 DB이며 KIS 미연결·인증 미확인, 주문·일지·실행 전략 각 0건을 GET으로 확인했다. 메인은 #156과 결합한 후보의 편차·만료·경고를 검증하고 사용자 화면 확인을 받는다.
