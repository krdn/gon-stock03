# 연결·설정에서 조회 상태 확인과 매매 설정 복귀

[배정 #162](https://github.com/krdn/gon-stock03/issues/162) · [전체 #149](https://github.com/krdn/gon-stock03/issues/149) · [선행 #113](113-settings-ux.md) · [주문 비교 사례](147-orders-ux.md)

모바일에서 연결 방법을 열면 로컬 새로고침이 첫 화면 아래로 밀렸다. 이제 서버에 있는 상태를 다시 읽는 버튼과 KIS에 전체 잔고를 요청하는 버튼이 같은 작업 영역에 보인다. 키·계좌 설정, 인증, 잔고를 개별로 표시하고, 조회 도중 끊기면 첫 결과에 부분 수신과 실패 원인, 이전 금액의 출처를 함께 표시한다.

## 변경 전후

기준 `04434fd`, 브랜치 `krdn/ux2-162-settings`. Chromium에서 같은 예시와 시각으로 안내 펼치기, 로컬 읽기, 브라우저 새로고침, 매매 설정 왕복, 부분 실패 후 복구를 수행했다. 좌표는 문서 상단 기준 CSS px다.

| 관측 | PC 1440×900 전 → 후 | 모바일 390×844 전 → 후 |
| --- | --- | --- |
| 미주입 첫 결과 / 안내 버튼 | 277 / 380 → 동일 | 249 / 341 → 동일 |
| 안내를 연 상태의 로컬 새로고침 | 377 → 380 | 879 → 341 |
| 안내를 연 상태의 세 단계 / 설명 제목 | 257 / 457 → 257 / 499 | 759 / 418 → 554 / 709 |
| 서버 접근 실패 후 로컬 새로고침 | 520 → 501 | 729 → 548 |
| 부분 수신 실패 후 KIS 재조회 / 이전 잔고 카드 | 380 / 513 → 401 / 543 | 341 / 699 → 362 / 754 |
| 매매 설정 링크 | 116, 1회 → 동일 | 84, 1회 → 동일 |

- 미주입·인증 미확인·잔고 미조회는 조작 없이 구별한다. 안내를 한 번 열면 누락된 항목 이름을 확인할 수 있다. 로컬 새로고침 1회는 GET이며 외부 조회를 발생시키지 않았다.
- 브라우저 새로고침과 매매 설정 왕복 후 안내를 다시 여는 횟수는 각각 1 → 0회였다. `/settings?guide=setup`은 안내 선택만 복원한다. Enter·Space로 조작하고 닫으면 `/settings`로 돌아온다. 매매 설정에서 연결 설정을 거쳐 다시 돌아온 뒤에도, 페이지를 새로고침한 뒤에도 예시 수동 한도는 7주였다.
- 이전에는 첫 결과가 ‘네트워크 오류’였다. 이제 ‘잔고 일부 수신 · 네트워크 오류’와 이전 전체 조회 기준임을 함께 읽을 수 있다. 직전 전체 조회 금액 22,000원과 시각을 유지했고, 두 화면에서 예시 재조회 1회가 전체 성공 응답을 받은 후에만 33,000원이 표시됐다. 계좌 요청은 브라우저 fixture가 응답했다.
- 모바일에서 안내 설명 제목이 낮아졌고 부분 실패 시 이전 잔고 카드도 55px 아래로 이동했다. 서버 복구와 단계별 상태를 먼저 보이는 쪽을 선택했다. 가로 넘침은 두 크기에서 0px였다.

## 설계 판단과 검증

- **유지** — 상단 매매 설정 링크는 두 화면에서 1회로 도달했다. 조회 중·재시도 대기·서버 단절의 차단, 지난 잔고 시각과 빈 보유 목록도 유지했다.
- **개선** — Gemini 4 Neon High가 지적한 모바일 안내로 인한 버튼 밀림, 부분 실패 근거 누락, 안내 복원 문제를 반영했다. 안내 토글은 현재 히스토리 항목을 갱신한다.
- **상세로 이동·중복 제거** — 누락된 환경변수 이름은 연결 방법 안에 모았다. 접힌 상태에서 차단 이유가 흐려진다는 리뷰 이견을 수용해 첫 결과에도 누락 개수를 표시한다. 서버 식별 및 관측 기록은 기존 상세에 둔다.
- **경로 근거** — Graphify에서 `Settings → useWorkbench`, `makeServer → recordConnection`을 확인했다. 화면에서 Store까지 단일 방향 경로는 찾지 못해 원문 경계를 대조했다. `src/App.tsx`의 refresh는 GET /api/state에서 로컬 SQLite 작업 상태와 KisClient 프로세스의 계좌 관측을 읽는다. `server/http.ts`의 POST /api/kis/check는 `KisClient.balance()`에서 전체 페이지가 성공할 때 계좌 잔고를 교체하고 성공·실패 이벤트는 Store를 통해 기록한다. [화면 상태](../../src/App.tsx) · [HTTP](../../server/http.ts) · [잔고](../../server/kis.ts) · [SQLite](../../server/store.ts)
- **구현 리뷰** — 수동 새로고침 응답이 끝난 후 자동 조회가 실패하면 이전 완료 문구까지 바뀌던 문제를 수정했다. 수동 요청 뒤 확인·미확인을 구분한다. 다음 자동 조회로 연결 상태가 달라지면 지난 피드백을 지우고 위쪽 결과에 현재 상태를 표시한다. 서버가 교체된 경우에는 앱이 새 인스턴스 경고를 표시한다. 서버가 조회 시작을 확인하기 전에 직전 조회 진행률이 잠시 보이던 문제를 수정했고 메모리의 잔고를 영구 저장값처럼 읽을 수 있는 표현을 고쳤다. 상태 계약에서 ISO 시각을 검사하므로 별도의 중복 파싱 검사는 추가하지 않았다.
- **모델 확인 범위** — 관측 검토·구현 리뷰·수정분 검토의 요청 모델과 CLI 초기화 모델은 모두 `gemini-4-neon-high`였다. 세 호출 모두 응답을 받았다. 수정분 검토에서 6개 중 5개가 통과했고 수동 GET 실패의 결과 표시가 남았다. 마지막 수정으로 실패 안내와 자동 단절 시 피드백 해제를 재현해 검증했다. 이 수정의 별도 모델 승인과 제공자 내부 모델·강도는 미확인이다.
- **검사** — 프로덕션 빌드, 설정 전 18건·후 21건, 변경과 관련된 공통 상태 4건 통과. #157 소유의 응답 지연 fixture 블록은 기준 브랜치와 해시가 일치했다. 검증 서버 프로세스 종료로 한 차례 접속 거부가 발생해 같은 4456에 사용자 임시 서비스로 재기동한 뒤 설정 전체를 다시 통과했다.

[검토용 설정](http://127.0.0.1:4456/settings) · [연결 방법 펼침](http://127.0.0.1:4456/settings?guide=setup). 이 포트는 빈 실행 환경의 메모리 DB로 키 미주입·인증 미확인·잔고 미조회 상태다. 부분 실패·기존 잔고는 합성 캡처와 테스트에서 확인한다. 실제 KIS 업무 호출, 4303 적용 및 사용자 직접 수용은 미실시다.
