# 대시보드의 계좌별 첫 판단과 이동

[작업 #150](https://github.com/krdn/gon-stock03/issues/150) · [상위 #149](https://github.com/krdn/gon-stock03/issues/149) · [1차 #18](18-dashboard.md) · [주문 화면 사례](147-orders-ux.md)

기준 `04434fdb`, 브랜치 `krdn/ux2-150-dashboard`. DEMO와 KIS의 첫 결과, 확인시각, 경고의 원인 및 전략 도착 환경을 같은 예시 상태로 PC 1440×900과 모바일 390×844에서 실측한다. 자동 검사는 4451의 독립 메모리 DB, 열람용 예시는 같은 포트의 전용 SQLite를 사용한다. 구현과 브라우저 검증 후 초안 PR에 연결하고 사용자 화면 수용을 별도로 기록한다.

## 화면에서 확인한 차이

11월 20일 오전 10시로 고정한 합성 예시다. DEMO 총자산 1,300원, KIS 저장 잔고 2,600원, KIS 미체결 1건과 불명·전송 중 1건, 정지된 KIS 전략의 관망 평가, 공통 위험 경고 1개를 넣었다. 문서 상단에서 각 항목 윗변까지의 거리(px)다.

- 두 크기 모두 KIS 전략 도달에 링크 선택과 환경 변경 2회가 필요했다. 변경 후 링크 1회로 KIS 환경에 도착하며 새로고침해도 유지한다. DEMO 전략과 위험 원인은 전후 모두 선택 1회다. 브라우저 뒤로가기로 대시보드에 복귀했고 이 동선의 쓰기 요청과 가로 넘침은 각각 0이었다. 사용자 소요 시간은 미측정이다.
- 도착한 전략 화면에서 DEMO 자동 재생 UI가 사라지고 정지된 KIS 전략과 저장된 평가 사유를 확인했다. 사유 본문은 PC 1,060px, 모바일 1,174px여서 아래로 스크롤해야 한다. 전략 화면 소유자에게 이 측정 결과를 전달했다. [PC 도착](../verification/assets/150-dashboard/after-pc-destination.png) · [모바일 도착](../verification/assets/150-dashboard/after-mobile-destination.png)
- 정상값과 위험 표시는 유지했다. DEMO/KIS 자산·출처·확인시각·전략과 주문 링크는 계좌별로 묶었고 경고와 원인 링크를 상단에 두었다. KIS 잔고와 주문 대조의 성공 시각은 따로 보인다. 잔고 계산식, 보유손익, 전략별 마지막 평가와 revision은 펼침 상세로 옮기고 환영 문구를 제거했다. 복수 경고나 긴 오류가 먼저 표시되면 첫 화면에 들어오는 항목 수가 달라진다.
- Graphify의 `explain Dashboard`는 `useWorkbench`와 `portfolioValue`를, `explain makeServer`는 HTTP 구성 경로를 찾았다. 방향 그래프는 Dashboard에서 Store까지 이어지지 않아 원문을 확인했다. `src/App.tsx`의 `refresh`가 `GET /api/state`를 조회한다. `server/http.ts`가 `Store.read/events`의 DEMO 상태와 원장 이벤트, `KisClient.connection`의 마지막 잔고, `PaperBroker.riskSnapshot`의 당일 대조와 저장 원장의 불명 건수를 조합한다. 전체 잔고와 당일 대조는 실행 중 메모리에 있으며 불명 주문은 SQLite 원장에서 읽는다. 대시보드를 여는 동작으로 증권사에 재조회하지 않는다.

## 검증과 검토

- 4451 전용 Playwright 설정에서 대시보드, 주문 통합, 전략 및 공통 상태 27건이 통과했다. 계좌별 선택·URL·새로고침·뒤로가기, 경고 원인, 키보드 Enter/Space와 초점, 정상 0원·0건, 미연결·오류·부분 실패·이전값·로딩·시각 만료, 합성 시세 누락을 포함한다. 포트폴리오 단위 4건과 프로덕션 빌드도 통과했다.
- 관측 검토는 중앙 설정 및 CLI 초기화 모델 `gemini-4-neon-high`로 성공했다. 경고 우선 배치·계좌 압축·기존 KIS URL·펼침 상세·환영 문구 제거를 반영했다. 최신 잔고와 미체결을 같은 시각으로 읽게 할 위험을 피하기 위해 두 기준 시각을 기본 화면에 유지했다. 서버 내부 모델과 추론 강도는 별도 미확인이다.
- [검토용 대시보드](http://127.0.0.1:4451/dashboard)는 이 워크트리 전용 SQLite 예시를 읽는다. DEMO 1,300원, KIS 미연결·잔고 미확인, 정지된 예시 KIS 평가 1건, 경고 1건이다. 저장 잔고 2,600원과 부분 오류는 위 캡처·브라우저 fixture에서 확인할 수 있다. 실제 주문·전략 실행·예약·실원장 사용을 수행하지 않았다. 사용자 직접 화면 수용은 대기 중이다.
- 첫 구현 리뷰는 FAIL이었다. DEMO 현재가 누락 원인, 서버 미확인 중 하단 시세·관심종목의 정상/빈 표시, 조회 중·실패·과거값 문구와 KIS 설정 링크, 전략 영역의 접근성 이름을 수정했다. KIS 잔고 만료 판정은 App의 공통 `freshness`가 이미 적용하므로 로컬 중복 계산 제안은 채택하지 않았다. 대신 상세를 접은 채 61초 후 경고가 실제로 보이는지 검사했다. 주문·입력 시각 비교에는 기존 서버 기준 시계를 사용한다.
- 현금 1,000원의 열람용 예시 DB로 공통 회귀까지 실행한 한 번은 DEMO 매수 확인을 전제한 기존 검사 1건이 시간 초과했다. 서로 다른 테스트 실행에 같은 메모리 DB를 재사용했을 때는 앞 실행이 저장한 예시 전략 1건 때문에 기존 전략 검사가 실패했다. 검증마다 표준 초기 DEMO 현금으로 별도 메모리 서버를 기동했다. 사용자에게 제공하는 예시 DB와 측정용 응답은 실제 원장과 독립되어 있다.
- 지정 모델 수정분 재검토는 **FAIL**이다. 서버보다 브라우저 시계를 120초 빠르게 고정하면 공통 로컬 상태가 ‘오래됨’으로 바뀌는 것을 재현해 App 소유 메인에 전달했다. 실제 미리보기는 브라우저와 서버가 같은 PC 시계를 쓴다. 잔고는 서버의 `KisClient.connection()`도 신선도를 판정한다. 나머지 두 지적에는 이견이 있다. 원문 `App.refresh`는 버전 역행 시 `invalidateConnection()`을 실제 호출한다. 주문 대조 시각은 응답 조립 전 저장되며 서버는 미래 체결 시각을 수용하지 않아 미래값 허용 제안은 적용하지 않았다. 관측·구현·수정분 3회 모두 CLI 초기화 모델을 확인했고 호출 오류는 없었다.
