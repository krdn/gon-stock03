# 알림·이벤트의 필터와 읽음 저장 범위

기준 `krdn/ux2-168-risk`의 `938114d`. 전용 4464와 예시 SQLite에서 PC 1440×900, 모바일 390×844의 첫 이벤트, 필터, 원인 이동과 읽음 저장 범위를 같은 데이터로 비교한다.

## 같은 예시 4건으로 확인한 변화

미읽음 KIS 전략 주의, 공통 위험 주의, DEMO 전략 안내와 이미 읽은 KIS 연결 오류를 사용했다. 숫자는 페이지 상단에서 잰 CSS px이다. Chromium에서 페이지를 열고 중요도를 ‘주의’로 바꾼 뒤 첫 원인 링크를 1회 열고 뒤로가기·새로고침을 수행했다.

| 최초 진입 위치 | PC 이전 → 변경 | 모바일 이전 → 변경 |
|---|---:|---:|
| 첫 이벤트 시작 | 703 → 593 | 826 → 670 |
| 첫 이벤트 제목 | 725 → 632 | 848 → 709 |
| 첫 원인 링크 | 840 → 684 | 964 → 761 |
| 읽음 저장 버튼 | 408 → 408 | 466 → 466 |

- 두 화면 모두 ‘주의’ 1회 선택 후 2건이 보였다. 이전에는 원인 링크가 DEMO 전략을 열고 돌아오면 4건이었다. 변경 후에는 KIS 모의 전략을 열고 돌아오거나 새로고침해도 주의 2건이다. 이전에는 주의를 다시 선택하고 저장 1회에 필터 밖까지 3개 ID를 보냈다. 변경 후 같은 보기에서 저장 1회에 2개 ID만 보냈다. 환경도 KIS로 좁히면 저장 대상은 1건이다.
- 모바일 첫 화면에서 첫 제목·원인 링크까지 보이며 두 크기 모두 가로 넘침은 0px였다. 선택 횟수는 브라우저 컨트롤의 값 변경 횟수다. ## 화면과 저장 동작

- **유지**. 최신순, 최근 최대 1,000건, 환경·읽음·시각 표시, 외부 발송 없음, ID 단위 읽음 트랜잭션을 보존했다. 클릭 직후 도착한 이벤트는 미읽음이다.
- **개선**. 중요도·환경·읽음을 교차 선택하고 수신·표시·목록 미읽음 건수를 분리했다. URL의 `level`·`env`·`read`는 허용한 값만 적용하며 공통 위험도 독립적으로 고를 수 있다. 네이티브 선택은 현재 주소를 교체해 뒤로가기가 중간 필터를 순회하지 않는다. 원인 링크에 목적지를 표시하고 해당 화면이 읽는 환경 쿼리를 사용한다.
- **상세로 이동**. 정상 실시간 상태는 한 줄로 접었다. 수신 중단·대조 필요·오류는 원인 링크와 함께 목록 위에 표시한다. 요청 ID는 각 행에서 키보드로 펼쳐 확인한다.
- **제거**. 초기 연결 전의 공통 예시 이벤트와 필터 밖 읽음 변경을 제거했다. 로딩·최초 실패·정상 빈 목록·필터 결과 없음·부분 수신·마지막 확인값을 구별한다. 불완전하거나 오래된 수신은 읽음 저장을 차단한다.
- **검토 이견**. 설계 검토에서 실제 처리 건수 표시를 제안했다. API는 변경된 행 수를 반환하지 않아 요청한 건수로 표시하고 최신 목록을 다시 읽는다. 환경 메타데이터가 빠진 과거 기록은 제목으로 재판정하지 않는다.

Graphify의 `Alerts → useWorkbench`, `makeServer → markPaperEventsRead`와 원문을 대조했다. Graphify에는 UI → Store 직접 경로가 없다. App의 `GET /api/state`는 작업 이벤트와 감사 원장을 합쳐 정렬한 결과를 읽는다. `POST /api/events/read`는 받은 ID에 한해 SQLite workspace 및 paper_event_read에 기록한다. 신규 전략 저장에는 검증한 환경과 strategies 목적지를 같은 트랜잭션에 기록한다. ## 검증과 수용

- 4464의 새 예시 SQLite에서 KIS 주의 미읽음 1건을 골라 원인 이동과 뒤로가기 후 읽음 저장을 1회 실행했다. 새로고침 후 해당 목록은 0건, 나머지 공통·DEMO 2건은 미읽음, 기존 읽음 1건은 그대로였다. 이 경로의 POST는 `/api/events/read` 1회였다.
- 메인이 추가 배정한 전략 저장 경로는 수정 전 KIS로 저장해도 알림에 DEMO가 표시되어 회귀 검사가 실패했다. 수정 후 DEMO·KIS 모의 각각 저장 1회, 전략 비활성, 알림 환경과 이동한 화면의 선택값 일치, 총 POST 2회 모두 `/api/strategies`였다. [브라우저 검사](../../tests/browser/alerts.spec.ts)
- 검토 주소는 [알림 전체](http://127.0.0.1:4464/alerts) 및 [KIS 주의 미읽음](http://127.0.0.1:4464/alerts?level=warning&env=kis-paper&read=unread)이다. 화면 측정은 같은 입력과 읽음 응답을 브라우저에서 고정한 비교이고, 위 SQLite 시나리오는 실제 로컬 API와 저장 결과를 별도로 확인했다.
- [외부 검토 기록](../verification/assets/179-alerts/review.json). 코드 및 합성 근거를 격리 디렉터리에서 Gemini 4 Neon High로 검토했다. CLI 초기 모델과 완결 응답을 대조했고 제공자 내부 실행 모델·추론 강도는 별도 미확인이다. [PR·CI 인수인계](https://github.com/krdn/gon-stock03/issues/179). 사용자 직접 수용·4303 반영·실제 장중 동작은 미검증이다.

구현 리뷰의 차단 P0/P1은 없었다. 부분·오래된 목록에서 결과가 0건일 때 필터 초기화, 차단 단계와 실시간 요약의 일치, 환경 미확인 원인 링크의 중립 표기를 보완했다. 과거 target 없는 이벤트의 서버 분류는 1차 규칙이 적용되며, 생성 당시의 환경을 복원할 근거는 부족하다. 이 변경은 새 전략 저장 시점에만 환경을 보존한다.

격리 Chromium 6건, 수정분 관련 4건, TypeScript·프로덕션 빌드가 통과했다. Graphify는 최종 코드에서 1,563노드·3,628연결로 갱신했다. Orca 미리보기에서도 KIS 원인 링크의 실제 선택값과 알림 복귀를 확인했다. 확인용 DB는 예시 4건·미읽음 3건, 활성 전략 0개, 재생·실시간 수신 정지 상태로 제공한다.

지정 모델 수정분 재검토는 PASS였다. 후속 비차단 지적에 따라 초기 로딩에만 중립색을 쓰도록 조건을 일치시켰고, 수신 후 로딩 사례를 포함한 상태 회귀 1건과 빌드를 다시 통과했다.
