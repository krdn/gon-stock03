기준은 `krdn/ux2-179-alerts@23bab52`이며 main `04434fd` 이후 같은 파일에서 수정된 위험관리·알림을 보존한다. `Journal`, 페이지 전용 CSS, 일지 검사와 증거를 담당한다. 4465 격리 서버에서 Chromium PC 1440×900과 모바일 390×844에 같은 빈 목록과 같은 종목·본문을 입력한다. 저장 → 검색 → 새로고침, 최초 빈 목록과 검색 0건, 실패와 저장 대기 중의 편집, URL·뒤로가기·키보드를 확인한다.

- 기준 버전에서 종목 선택 → 본문 입력 → Enter 저장 → 검색어 입력 → 새로고침까지 5행동, 메모 POST 1회였다. 새로고침 후 두 화면 모두 본문 검색어가 사라졌다. 서버 오류 응답 뒤에는 작성 중 메모가 남았다. [좌표와 입력 조건](../verification/assets/182-journal/before.json)

페이지 안에서 최초 작성 위치를 높이고, 저장한 종목을 이름·코드·본문으로 다시 찾을 수 있게 한다. 브라우저 주소에 자유 입력을 싣지 않고 검색 복원을 검증한다. 실제 저장 기능과 실패·대기 중 초안 보호는 기존 회귀와 함께 확인한다. 기준 실측을 지정 모델로 검토한 후 결정과 이견을 기록한다.

## 결정과 결과

- **유지**. 최신순·본문 전체·저장 시각을 유지한다. 저장 응답을 기다리는 동안 종목이나 본문을 바꾸면 새 입력을 지우지 않는다. 실패 때도 초안을 유지한다. 서버 응답이 끊긴 경우 저장됐을 수 있으므로 ‘전체 기록 확인’은 검색을 지우고 GET 조회만 수행한다.
- **개선**. 기록을 종목명·코드·본문으로 찾는다. 조회한 내용과 동일한 이름·코드를 행에 표시하며 검색 결과와 전체 건수를 구분한다. 부분 수신·오래된 응답에서는 받은 기록 안의 일치 건수만 표시한다. 검색은 같은 방문의 새로고침·뒤로가기에서 복원한다. 다른 방문에 복사할 URL은 `/journal`이고 작성 본문은 브라우저 방문 기록에 보관하지 않는다.
- **작성 위치**. 빈 목록의 종목 선택·본문·버튼을 압축했다. 기록이 있는 모바일에서는 ‘메모 작성’ 한 번으로 목록 길이와 관계없이 종목 선택에 초점을 보낸다. 1,450자 예시 5건에서 464px의 바로가기를 한 번 누르면 6,300px에 있던 종목 선택에 초점이 옮겨졌고, Tab으로 본문과 저장에 접근했다. [긴 기록 실측](../verification/assets/182-journal/long-notes.json)
- **상세·제거**. 각 행에 출처를 반복하지 않고 목록 머리에 ‘로컬 저장’을 표시한다. 미확인 상태의 0건 판정, 최초 빈 화면의 검색창과 빈 상태 장식 표시는 제거했다. 수신 전·오류·부분 수신·마지막 수신값을 구별한다.
- **설계 리뷰와 이견**. Gemini 4 Neon High가 지적한 검색 누락, 모바일 폼 밀림, 최초 응답 전 빈 화면과 오류 복구를 반영했다. 긴 본문을 접는 제안은 저장 기록을 다시 확인하려면 조작이 늘어나므로 채택하지 않았다. 최초 서버 확인 전에는 서버 연결 시 화면 재생성으로 사라질 초안 입력을 잠시 막고, 한 번 수신한 뒤에는 부분 수신·연결 중단 때도 편집을 허용한다. 오류 알림은 기존 공통 접근성 알림과 폼의 지속 안내를 함께 사용한다.

## 검증과 수용

- 격리 메모리 DB와 4465 전용 Playwright 구성에서 신규 Chromium 6건과 기존 일지 9건이 통과했다. 이름·코드·본문 검색, 0건·지우기·초점 복귀, URL·새로고침·뒤로가기, 키보드 저장, 최초 오류·부분·마지막 확인값, 서버가 저장한 뒤 응답만 유실된 경우 재전송 없는 확인을 검증했다. SQLite 오류 롤백·파일 재시작 등 관련 단위/API 3건도 통과했다. [독립 검사](../../tests/browser/182-journal.spec.ts)
- [4465 검토 화면](http://127.0.0.1:4465/journal)은 이번 작업 전용 SQLite이다. 두 화면에서 예시 메모를 한 건씩 실제 로컬 API로 저장해 이름·본문 검색과 새로고침을 확인했다. 확인용 원본 데이터는 SK하이닉스 ‘분할’, 삼성전자 ‘거래량’ 두 건이고 재생·활성 전략은 0이다. Orca 브라우저에서 ‘분할’ 검색 후 새로고침 시 일치 1 / 전체 2건을 다시 읽었다. [실제 로컬 API 결과](../verification/assets/182-journal/preview.json)
- 로컬 fixture·기술 검증을 수행했다. 운영 화면 반영과 사용자 직접 수용은 대기 중이다. 이 페이지는 KIS 업무 호출을 사용하지 않는다.

처음 구현 리뷰는 5분 제한으로 중단돼 완결 판정을 받지 못했다. 반환된 P2 세 건에 따라 부분 수신 중 검색 0건의 범위를 표시하고, 편집 중 선택 종목이 사라지면 재선택 전 저장을 막고, 같은 경로의 다른 방문도 해당 방문 검색어를 복원하도록 수정했다. 별도 필터로 재실행한 격리 Chromium 15건이 모두 통과했다. 최초 재실행에서 작업 폴더 이름이 테스트 경로 필터에도 일치해 전체 suite가 선택된 실행은 중단했다. 메모리 DB에서 15건으로 제한했으며 최종 preview는 별도 예시 SQLite에 두 건을 저장해 제공한다.

같은 지정 모델의 수정분 재검토는 완결 PASS로 앞선 세 수정을 확인했다. 이때 남긴 P2 두 건까지 반영해 최초 부분 응답으로 종목이 비었을 때 ‘미확인’ 표시, 이후 첫 종목 선택, 선택이 비활성일 때 ‘메모 작성’의 본문 초점을 확인했다. 모든 호출의 CLI init은 `gemini-4-neon-high`였고 제공자 내부 모델·추론 강도는 별도 미확인이다. 최종 TypeScript·프로덕션 빌드가 통과했고 Graphify는 1,571노드·3,642연결로 재생성했다.
