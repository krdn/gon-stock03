# KIS 모의 매매 화면 2차 검증

[배정 #166](https://github.com/krdn/gon-stock03/issues/166) · [전체 #149](https://github.com/krdn/gon-stock03/issues/149) · [선행 PR #159](https://github.com/krdn/gon-stock03/pull/159)

기준 `af44cd5`. 4458 독립 예시에서 PC 1440×900·모바일 390×844의 종목·주문 입력, 일반 설정 왕복, 계좌 대조, 접수·불명 복구·잔량 취소를 확인한다.

## 직접 확인할 화면

- [복구·부분체결·잔량 취소 예시](http://127.0.0.1:4458/paper?code=005930&sample=166). 새 탭에는 불명 1건과 부분체결 1건이 보인다. ‘불명 주문 보기’로 이동한 뒤 복구 조회 → 후보 확인 → 연결을 진행한다. 부분체결 예시는 3주 중 1주 체결, 잔량 2주다. 취소 확인창을 닫거나 2주 취소와 뒤이은 대조까지 확인할 수 있다.
- [빈 주문 입력·접수 예시](http://127.0.0.1:4458/paper?code=005930&sample=166-input). 시세를 조회하고 수량을 입력해 일반 설정을 왕복하거나 합성 주문을 확인·접수할 수 있다. 합성 원장과 복구 결과는 탭의 sessionStorage에만 존재한다. 새 브라우저 컨텍스트에서 처음부터 재현할 수 있다.
- 기존 서버와 빌드를 빈 환경으로 실행했다. 메모리 DB의 초기 수동 한도는 5주, KIS 원장은 0건이다. 예시 링크에서는 [fixture](../verification/assets/166-paper/sample.js)가 KIS 조회·접수·취소·복구 결과를 브라우저 안에서 반환한다. 로컬 상태·설정 읽기와 일반 수량 설정 저장만 격리 서버에 전달한다. 검증 후 한도를 5주로 복원했다. fixture는 4458의 검사 빌드에만 삽입한다.

## 같은 작업의 전후 실측

수치는 문서 상단에서 요소까지의 거리(px)다. 두 예시 주문이 있는 같은 화면에서 종목 조회 → 매도 3주·72,500원 입력 → 수동 한도 5→8 저장 → 새로고침·뒤로·앞으로·5주 복원·명시적 복귀 → 당일 대조 → 불명 복구 → 잔량 취소를 조작했다. 입력 예시에서는 빈 원장에서 75,000원 2주 확인창을 Escape로 닫고 다시 열어 합성 접수를 1회 수행한 뒤 새로고침했다.

## 결정과 근거

- 개선. 종목 조회와 주문 입력을 연이어 배치했다. 현재가의 수신 시각과 수동 당일 대조 시각을 각 결과에 표시한다. 원장의 미확정 수량에는 ‘미확정’을 붙였다. 주문 관리 링크에서 KIS 원장 보기를 연다. 불명 원주문은 가로 스크롤 없이 찾아 확인할 수 있다.
- 상세로 이동. 최근 수정 일봉은 실제 응답 개수로 펼치고, 식별 정보에는 거래일·증권사 번호·앱 요청 ID를 모았다. 확인·복구에 필요한 직접 입력과 명시적 동의는 계속 표시한다.
- 제거. 빈 일봉의 빈 그래프와 중복 수신 시각을 제거했다. 시세 요청의 대기·실패, 일봉 0개, 당일 주문 0건, 원장 오류, 대조 실패 후 과거값을 구분한다.
- 유지. 실시간 수신·대조 버튼과 중단 경고, 일반 설정·URL·뒤로/앞으로 복원, 미확인 요청 ID 보존, 복구 후보가 유일할 때만 연결, 일반 취소 금지·한정 취소 확인·취소 후 대조를 보존했다. 실시간이 필요하거나 진행 중·오류 상태이면 상단에서 상태를 확인하고 제어 영역으로 이동한다. 실시간 제어 영역은 고정해 수신 상태가 바뀌어도 같은 버튼을 유지한다.
- Gemini 4 Neon High 설계 검토의 포커스 이동, 시간 출처, 과거값·실패·일봉 없음 구분과 취소 후 전체 폭 검사를 반영했다. 불명 주문 여러 건 중 첫 복구 가능 주문으로 이동한다. 건별 상태와 직접 조회 버튼은 각 행에 둔다. 기존 수량·시세·가드 계약과 명시적 취소 확인 절차를 사용한다.
- Graphify의 `Paper.tsx`, `loadLedger`, `displayPaperOrders`, `PaperBroker` 노드를 원문과 대조했다. `/api/kis/ledger` → `Store.displayPaperOrders` → SQLite `paper_orders` 및 과거 대조 기록 읽기다. 시세는 수동 `kis/market`, 당일 계좌는 `kis/orders`다. `PaperBroker`의 복구 조회·연결·취소는 `paper_audit`와 취소 시도 기록을 사용한다. Graphify가 찾은 양방향 최단 경로는 공통 타입을 거치는 2단계이므로 HTTP와 저장 동작은 원문에서 확인했다.

## 리뷰와 검증 범위

Gemini 4 Neon High 구현 리뷰에서 P1 1건과 P2 네 묶음을 받았다. P1에서 지적한 연결 상태의 null 접근은 `App`의 초기화, `Workbench.connection` 필수 타입, 상태 응답 스키마를 대조해 재현 경로가 없음을 확인했다. 통계의 접근 표기를 필수 타입과 일치시켰다. 시장가 취소 표기 제안은 원주문 검사에서 양수 지정가만 허용하는 #116 계약을 확인해 기존 표시를 유지했다.

미확인 요청을 다시 확인할 때 현재 입력과 최초 주문 종목이 다르면 최초 주문 종목을 기준으로 실시간 가드를 검사한다. 거래정지 가드를 폼과 버튼에서 공유하고, 원장·대조·복구 실패 사유와 처리 중 표시를 보완했다. 차단 경고의 보조기기 알림, 키보드 초점 여백과 실시간 제어 위치를 수정했다. 대조 실패 뒤에는 취소 대상을 차단한다. 지정 모델의 수정분 판정과 최종 원격 CI는 [배정 이슈](https://github.com/krdn/gon-stock03/issues/166)에 남긴다.

TypeScript·프로덕션 빌드 및 전용 포트의 Chromium 회귀 39건이 통과했다. 비교·수정 검토는 공개 가능한 코드와 합성 근거를 임시 디렉터리에서 전달했다. CLI가 보고한 초기화 모델은 `gemini-4-neon-high`이며 서버 내부 모델과 실제 추론 강도는 독립 확인하지 못했다.

서버/API와 공용 컴포넌트는 기존 계약을 쓴다. 모바일의 당일 계좌 표에서는 전체 열을 가로로 확인하며 앱 주문 원장의 핵심 정보와 복구는 화면 폭 안에 놓인다. 기술 검증은 Chromium과 격리된 합성 결과에 한정한다. 실제 KIS 업무 호출·장중 체결은 미측정이며 사용자 직접 수용, #159 통합 후 main 재검증, 4303 반영은 메인 세션에 남는다.
