# 포트폴리오 계좌 출처와 조회 시각

[이슈 #174](https://github.com/krdn/gon-stock03/issues/174) · [초안 PR #176](https://github.com/krdn/gon-stock03/pull/176) · [상위 #149](https://github.com/krdn/gon-stock03/issues/149) · [선행 PR #156](https://github.com/krdn/gon-stock03/pull/156) · [1차 포트폴리오](16-portfolio.md) · [주문 화면 비교](147-orders-ux.md)

기준 `28e0cdd`. 4460의 격리된 동일 예시로 두 화면 크기에서 계좌 전환, 예수금·손익·보유 확인, 원인·종목 이동과 복원을 비교한다. KIS 전체 성공 시각과 DEMO 로컬 확인 시각, 이전·부분·미확인 상태를 검증한다. 대시보드 계좌 확인 시각은 UTC와 서울에서 비교한다. 사용자 직접 수용은 별도다.

## 화면에서 확인한 차이

변경 전후 모두 KIS 예수금 1,000원, 주식 평가액 1,000원, 2종목의 합산 손익 0원인 예시를 사용했다. 별도 DEMO는 같은 로컬 합성 보유내역이다. 아래 수치는 첫 진입 시 문서 상단에서 값 또는 링크 상단까지의 CSS 픽셀이다. 스크롤 횟수와 사용자가 읽는 시간은 미측정이다.

| 경로와 측정 대상 | PC 1440×900 전 → 후 | 모바일 390×844 전 → 후 |
|---|---:|---:|
| 정상 KIS 첫 평가금액 | 523 → 504 | 683 → 609 |
| 정상 KIS 첫 종목 링크 | 773 → 689 | 1,050 → 804 |

- KIS 진입 후 예수금·손익·확인 시각은 추가 선택 0회, 종목 상세는 1회다. DEMO 전환과 종목 열기는 전후 모두 2회다. 변경 전에는 KIS 실제 시세에 도착했고 뒤로가거나 새로고침하면 DEMO 선택이 풀렸다. 변경 후 합성 시세에 도착하고 URL의 `environment=demo`로 복원했다. 두 크기에서 이 이동으로 발생한 POST는 0건이다.
- KIS 부분실패에서 이전 전체 성공 스냅샷과 설정 원인 링크를 함께 보여 준다. 원인 링크는 1회로 설정을 열고 뒤로가면 같은 계좌가 보인다. 검토용 예시의 성공 시각은 오전 10시, 다음 페이지 실패를 관측한 시각은 오전 10시 1분이다. 선택 계좌와 대시보드 요약의 KST 시각은 UTC·서울 브라우저에서 일치한다.
- 0원·0종목과 미확인을 구별한다. DEMO 최초 서버 조회 오류에서는 합성 초기값을 숨긴다. 조회 성공 후 연결이 끊기면 마지막 금액을 경고와 함께 유지한다. KIS의 미조회, 수동 조회 중, 부분실패, 오래된 값, 복구, 가격 누락과 소수점 평균가도 검사했다.

## 결정과 근거

- **유지** — 수량·소수 평균가·비용 전 평가손익, 가격 누락 시 전체 합계 산출 불가, 전체 페이지 성공 후 KIS 잔고 교체, 현금 비중 차트를 유지했다. KIS 예수금과 주문 가능 금액의 차이를 금액 바로 아래에서 설명한다.
- **개선** — 선택 계좌 출처와 금액 기준 시각을 묶고, DEMO도 모바일에서 표를 세로로 읽을 수 있게 했다. 기존 종목 링크에 DEMO 모드를 전달하며 계좌 전환은 URL 이력에 남긴다. 미지정·미지원 환경은 기본 KIS 조회 화면으로 간다. 수동 잔고 조회 동작은 유지한다.
- **상세 이동** — 계산 근거, API 참고 총평가액 9,999원과 자산 배분을 ‘평가 기준과 자산 배분’에서 확인한다. 금액을 볼 때는 펼칠 필요가 없다. **제거** — 미조회 DEMO 초기 목업 금액과 선택 환경의 반복 안내를 제거했다.
- **Graphify와 원문** — `graphify explain Portfolio` 및 `graphify path Portfolio portfolioValue`는 UI의 컨텍스트와 계산 함수로 연결됐다. `useWorkbench → Store`의 직접 경로는 찾지 못했다. 원문에서 [앱 조회](../../src/App.tsx), [HTTP 스냅샷 구성](../../server/http.ts), [DEMO SQLite](../../server/store.ts), [KIS 전체 페이지 수신](../../server/kis.ts), [평가 계산](../../shared/portfolio.ts)을 대조했다. DEMO의 보유내역은 로컬 저장 상태에서 읽고 KIS 잔고는 서버 메모리의 마지막 전체 성공값을 읽는다.
- **설계 검토** — Gemini 4 Neon High는 위 결정을 지지하고 DEMO 수신 화면과 키보드 복원 검증을 조건으로 제시했다. `/trade`와 실제 화면에서 DEMO 모드를 확인했다. 미래 환경 enum 추가와 주문 가능 금액 추정은 범위에 넣지 않았다. 공통 셸의 모바일 점유 공간을 메인에 전달했고, 메인이 추가 위임한 공통 관측·최종 성공 시각에 동일한 KST 표기를 적용했다.

## 검토용 실행 화면

[부분실패 KIS](http://127.0.0.1:4460/portfolio) · [DEMO](http://127.0.0.1:4460/portfolio?environment=demo) · [대시보드](http://127.0.0.1:4460/dashboard). 같은 작업트리의 빌드 결과와 기존 서버를 4460에서 실행한다. 예시 메모리 DB, 외부 fetch 차단, 읽기 전용 요청만 허용한다. KIS 보유 2종목, 예수금 1,000원, 원장 주문 0건, DEMO 재생 꺼짐을 확인했다. Orca 브라우저에서 부분실패와 이전 전체 성공·최근 관측을 확인하고, DEMO 종목 링크에 키보드로 진입해 합성 트레이딩과 뒤로가기를 확인했다. 새로고침 버튼의 상태 전이는 Playwright에서 모의 응답으로 검증했다. 4460 검토 서버는 쓰기 요청을 405로 돌려준다. 실제 계좌·거래, 실제 장중 데이터와 사용자 직접 수용은 미검증이다.

## 검사와 남은 범위

초기 Gemini 구현 판정은 FAIL이었다. 새로고침 중의 빈 상태·원인 링크, 반올림한 0원 손익의 부호·색, 수량 구분자와 매입·현재 단가의 원 단위를 수정했다. 모바일 원인 링크의 터치 높이는 44px다. KIS 평균가와 가격은 API 경계에서 이미 숫자·양수 또는 null로 검증하므로 화면에 중복 방어를 넣지 않았고, 기존 소수점 원가는 보존했다. 수정분 Gemini 검토도 FAIL(P2 1건, P3 1건)이었다. 조회 전에는 원인 경고를 표시하지 않고 설정 안내를 제공하며, 최초 KIS 탭 로딩 중에는 로컬 서버를 읽는다고 표시하도록 수정했다. 초기 응답을 보류한 브라우저 검사와 오프라인·부분실패 회귀로 재검증했다. 이 두 지적은 먼저 격리 브라우저에서 재검증했다. 추가 위임된 공통 시각 표기 리뷰에서 Gemini 4 Neon High가 공통 시각 PASS, 잔여 P2·P3 각각 해소 PASS를 반환했다. 레이아웃 좌표는 별도로 직접 실측했다. 지정 모델의 설계·구현·수정분 검토와 최종 CI는 [이슈 #174](https://github.com/krdn/gon-stock03/issues/174)에 기록한다. CLI 초기화에서 확인한 모델과 제공자의 내부 모델·강도는 구분한다.

전용 포트에서 Chromium 20건(포트폴리오 11, 선행 대시보드 9), 포트폴리오 계산·스키마 단위 4건 및 TypeScript·Vite 빌드를 통과했다. 초기 URL 회귀는 수정 전 같은 조건에서 실패했다. Graphify AST 추출은 CSS에 대한 코드 경로를 제공하지 않아 전용 CSS는 원문과 렌더링으로 확인했다. 모바일에서 예시 123,456,789,012,345원을 표시할 때 페이지 폭이 430px로 늘어나는 문제도 재현해 금액 줄바꿈을 허용했다. 수정 후 페이지 폭은 390px였다. 모바일 부분실패에서 첫 종목은 첫 화면 아래 940px에 있다.

추가 위임으로 [공통 상태](../../src/components/ui.tsx)·대시보드·포트폴리오가 KST 표기를 공유한다. 같은 부분실패 예시에서 UTC·서울 모두 관측 `2026-11-20 10:01:00 KST`, 최종 전체 성공 `2026-11-20 10:00:00 KST`이며 미조회 시각은 ‘없음’이다. 두 시각은 1440px에서 같은 줄, 390px에서 두 줄로 보인다. 포트폴리오와 지난 주문 모두 가로 넘침이 없었다. 모바일에서 부분실패 시 계좌 버튼과 잔고 새로고침은 499~536px, 경고는 597~700px, 원인 링크는 650~694px, 첫 평가금액은 746~772px로 모두 첫 화면에 보인다. PC에서는 같은 버튼이 410~447px이고 첫 금액은 577px다. 정상 모바일 계좌 버튼은 473px, 첫 금액 609px, 첫 종목 링크 시작은 804px다. 기존 공통 상태 줄과 긴급정지 경고를 유지했다. 전용 포트에서 #147 과거 목록·보기 복원·부분실패를 포함한 주문·포트폴리오·대시보드 회귀 36건을 통과했다.

초기 KST 표기 변경 커밋 `4dbee29`에서는 원격 push·PR 검사 모두 390px 대시보드의 KIS 전략 링크가 92.7%만 보여 실패했다. 날짜·초·KST를 보존한 24시간 표기로 바꾸고 기존 링크 전체 노출 기준을 재검증했다.
