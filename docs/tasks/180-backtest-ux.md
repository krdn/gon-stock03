# 저장 일봉 선택과 백테스트 재현

[작업 #180](https://github.com/krdn/gon-stock03/issues/180) · [전체 #149](https://github.com/krdn/gon-stock03/issues/149) · [데이터 전달 #173](https://github.com/krdn/gon-stock03/issues/173) · [1차 백테스트](21-backtest.md) · [주문 화면 비교](147-orders-ux.md)

기준은 전략 스튜디오 PR #178의 `4f341ab`이다. 4463의 격리 예시에서 저장 일봉과 합성 출처를 각각 데이터 화면부터 확인하고, 고정 입력의 저장·불러오기·재현을 PC와 모바일에서 비교한다.

두 화면 크기 모두 데이터 화면에서 원주가 00088K를 골라도 백테스트의 수정주가 000660이 열렸다. DEMO 링크도 저장 모드로 열렸다. 모바일의 일봉 선택은 y=1,689px, 실행은 2,322px였다. 실행 직후 스크롤은 2,803px였고 결과 시작은 876px였다. PC의 대응값은 966·1,639·1,347·790px였다.

Graphify의 `Backtest`·`createExperiment` 설명을 원문과 대조했다. `Research.tsx`가 출처·수집을 로컬 기본값으로 선택했다. 저장 모드는 `GET /api/data/daily` → `POST /api/backtest/daily` → `server/backtest.ts:createExperiment` → SQLite `daily_runs/daily_bars` 읽기·`backtest_experiments` 저장으로 이어진다. 재현은 고정 스냅샷을 읽는다. 합성은 `/api/backtest`에서 DEMO 가격 이력을 사용한다. Graphify가 추론한 수수료 함수 경유의 최단 경로는 실제 HTTP 경로에서 제외했다.

## 리뷰와 검증

- **유지** 기존 기본 수집 선택과 명시적인 저장 실험 불러오기, 가격 정책, 고정 입력·결과 해시 및 재현 엔진을 유지했다. 재현은 저장된 스냅샷의 입력으로 수행한다.
- **개선** URL의 출처·수집 ID를 목록에서 대조한다. 잘못된 조합·중복과 사라진 기록에는 복구 방법을 표시한다. 입력을 먼저 배치하고, 완료 후 결과에 포커스를 옮긴다. 두 실험 모두 사용한 비용과 체결 시점, 입력 오류와 고정 결과를 구별한다.
- **상세로 이동** 비용 산식·평가 가정은 펼침으로 옮겼고, SHA256·엔진·수집 출처·원본 JSON은 기존 펼침에서 확인한다.
- **제거** 첫 실험 전 중복 원칙과 빈 차트 자리를 지웠다. DEMO에서 입력이 바뀌면 직전 결과가 사라진다.
- **의견 차이** 설계 리뷰는 개별 실험 ID의 URL 저장도 제안했다. 이번 전달 계약은 출처·수집 ID까지다. 새로고침 후 실행·재현은 자동 요청하지 않고 사용자가 저장 실험을 선택해 불러온다. 처음 설계 검토의 좌표 첨부 누락은 구현 리뷰 입력에서 실제 좌표와 행동 목록으로 보완했다.
- 격리 브라우저에서 키보드 출처 변경·결과 초점·Space 상세, 새로고침·앞뒤 이동, 빈 목록·부분 수집·달력 미대조·사라진 ID·늦은 응답·503 재조회 복구, 비용 입력 변경·짧은 가격 표본·재현 오류를 확인했다. 대표 작업의 POST는 로컬 일봉 실험, 재현, 합성 계산 각 1건이었다.

구현 리뷰는 PASS와 함께 P2 2건, P3 2건 및 표시 개선 의견을 남겼다. DEMO에 기본 종목이 없을 때 표시한 종목을 사용하고, 빈 목록에서는 실행을 차단했다. 재현 불일치와 응답 형식 오류에 각각 경고를 표시한다. 성공 응답으로 이력을 갱신해 결과 포커스와 실행 후 목록 로딩이 겹치지 않게 했다. 최초·재조회 오류를 구분하고 거래 0건의 원인 단정을 제거했다. 390px에서 날짜·비용은 입력칸이 넘치지 않아 두 열을 유지하고 아래선을 맞췄다. 수집 변경 후 수수료 7.5bp가 1.5bp로 초기화되며 초점을 잃는 문제도 재현해 고쳤다.

같은 모델의 수정분 리뷰도 PASS였다. 리뷰 입력에 생략한 JSX의 오류 알림과 선택 초점은 브라우저 검사로 확인했다. 후속 참고 의견을 반영해 저장 체결일 누락은 미확인으로 표시하고, 재조회 성공 때 선택 초점을 복원한다.

검토 요청과 CLI 초기화 모델은 `gemini-4-neon-high`였다. 서버 내부 모델과 추론 강도는 독립적으로 확인되지 않았다. 로컬 빌드·백테스트 단위/API 6건·페이지 회귀 8건과 PC·모바일 대표 작업을 통과했다. 번들 500kB 초과 경고가 남았다. [참조한 공식 라우터 문서](https://reactrouter.com/7.18.5/api/hooks/useSearchParams) · [중복 검색 인자 처리](https://developer.mozilla.org/en-US/docs/Web/API/URLSearchParams/getAll).

## 결합 검사에서 발견한 재선택 회귀

메인의 결합 커밋 `49f4fb2`에서 데이터 → DEMO로 이동한 뒤, 같은 DEMO를 다시 선택하면 동일 URL이 방문 기록에 쌓였다. #177의 기존 Chromium 검사에서 뒤로 한 번 후 `/backtest?source=demo`에 머무는 실패를 4463에서 재현했다. 저장 일봉에서도 같은 출처를 재선택하면 주소의 수집 ID가 사라질 수 있었다.

유효한 현재 출처·정책·수집을 다시 선택하면 주소·입력·표시 중인 결과를 유지한다. 다른 수집을 고를 때의 비용·초점 전달, 다른 실험 불러오기와 잘못된 URL의 명시적 복구는 기존 경로를 사용한다. 탐색·재선택 요청에서 POST는 0건이었고, 고정 입력 재현은 버튼을 눌렀을 때만 요청했다.

4463의 임시 복사본에서 `49f4fb2`에 백테스트 수정만 적용해 데이터·백테스트·전략 Chromium 32건이 통과했다. #177의 원래 단언은 그대로 검사했다. 모바일 390×844에서 재선택·고정 실험·데이터 왕복 3건도 통과했다. 작업 브랜치의 빌드·백테스트 화면 9건·종목을 바꾸는 실험 불러오기/재현 검사, #177을 함께 빌드한 최종 예시의 PC·모바일 실험도 통과했다.

지정 Gemini 4 Neon High의 재선택 수정 검토 결과는 차단 결함 없음이었다. 비차단 의견에 따라 현재 출처만 다시 선택하는 경우의 조건을 명시하고 결과 초기화 예외를 두 수집 선택기에 한정했다. CLI init은 지정 모델과 일치했으며 서버 내부 모델·강도는 미확인이다.
