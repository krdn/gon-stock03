# #92 모의 실시간 구독 경로

PR91 통합 기준 78573f3. 공식 국내주식 예제와 모의 연결 URL을 맞추고, 시세·체결통보 구독 확인, 새 시세와 REST 대조를 검증한다. 읽기전용 검증 프로세스의 단절과 같은 검증 DB를 연 새 프로세스의 명시 재시작을 비교한다. 주문·취소·전략 전송 승인은 없다.

필수 자료는 [#92](https://github.com/krdn/gon-stock03/issues/92), [#25](https://github.com/krdn/gon-stock03/issues/25), server/realtime.ts와 tests/realtime.test.ts다.

## 11월 18일 장중 검증 (KST)

- 공식 예제의 경로를 모의 호스트에 적용했다. 최초·재연결에 전달된 URL 두 개를 검사하는 회귀는 PR91 코드에서 실패했고 수정 후 실시간 검사 28개, 전체 단위 검사 216개와 빌드가 통과했다. [공식 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_user/domestic_stock/domestic_stock_examples_ws.py)
- 새 검증 DB, 비활성 전략, 승인 없는 PaperBroker로 실행했다. REST는 접속키·토큰 인증과 잔고·당일 주문내역 조회만 허용했다. 수정 URL을 그대로 사용해 시세·모의 체결통보 두 구독의 성공 응답을 받고 10:16:23 실제 시세와 REST 대조 ready를 확인했다. 검증 소켓을 종료하자 disconnected·주문 차단, 자동 재연결 뒤 두 구독 성공, 10:16:26 새 시세와 명시적 REST 대조 ready를 확인했다. 검증 원장 주문 0건, 주문·취소·전략 전송 0회.
- 이전 10:06 실패의 로컬 원인은 명시 시작당 누적 3회 한도였다. 이전 검증 DB의 이벤트를 읽기전용으로 조회했다. 10:06:04 최초 연결 종료, 05초 첫 재시도에서 두 구독 확인, 11초 대조 후 강제 단절, 13초·17초 두 재시도 모두 구독 확인 전 종료, 이후 재시도 없음. 서버 측 종료 사유는 당시 기록에 없다. 한도와 기존 재개 조건을 보존했다.
- 인증 없는 handshake 비교에서 루트도 한 차례 열렸고, 다른 시도에서는 루트와 공식 경로 모두 ECONNRESET이었다. 과거 단절 전체를 경로 하나로 설명할 수 없다. 공식 경로의 실제 수신은 위 두 구독과 시세로 확인했다.
- 같은 검증 DB로 새 프로세스를 시작할 때 stopped·required=true·ordersAllowed=false를 관측했다. 첫 명시 재시작은 REST 토큰 요청 단계에서 대조 실패, 다음 시도는 45초 내 ready 미도달이었다.
- 10:18 재시작에서도 최초 연결과 1·2·4초 재시도가 모두 구독 확인 전에 닫혔다. 통합 SHA 재검증 결과와 최종 CI는 이슈 #92에서 확인한다.
- 외부 리뷰는 agy에 gemini-4-argon-high와 effort high를 직접 지정했다. init 모델 일치, 결과 SUCCESS/PASS, 차단 결함 0개. 제공자 내부의 실제 모델·effort는 독립 확인할 수 없었다. Graphify 코드 그래프와 보고서를 갱신했다.
