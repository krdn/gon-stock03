# 설정 왕복 후 모의 주문 입력 복원

기준 [#154](https://github.com/krdn/gon-stock03/issues/154) · 상위 [#149](https://github.com/krdn/gon-stock03/issues/149) · 설정 화면 [#152](https://github.com/krdn/gon-stock03/issues/152). 시작 main `04434fd`, 브랜치 `krdn/ux2-154-paper-return`. 관련 계약은 [모의 매매 #14](14-paper.md)와 [일반 한도 설정 #122](122-trading-settings.md)에서 확인할 수 있다.

## 바뀐 동작

PC와 모바일에서 일반 수량 한도를 저장하고 설정 화면을 새로고침했다. 브라우저 뒤로 가기에서는 입력이 살아 있었지만, 앞으로 간 뒤 ‘주문 입력으로 돌아가기’를 누르면 매도 주문이 매수 1주로 바뀌고 지정가가 사라졌다. `Paper.tsx`가 첫 복귀 때 공용 레코드를 삭제해 두 번째 복귀에 쓸 입력이 없었다.

| 명시적 복귀 직후 | 종목 | 방향 | 수량 | 지정가 | 주문 금액 |
| --- | --- | --- | ---: | ---: | ---: |
| 수정 전 | 000660 | 매수 | 1주 | 빈 값 | 0원 |
| 수정 후 | 000660 | 매도 | 4주 | 72,500원 | 290,000원 |

설정으로 넘어간 주문 입력에 전용 키를 부여했다. 뒤로 가면 원래 이력의 입력을 열고, 복귀 링크는 키와 종목이 일치할 때 그때의 입력을 연다. 복귀 후 편집한 값은 현재 이력에 보관한다. 시세 재조회, 주문 확인, 전송 결과 미확인 요청의 동일 ID 대조는 기존 절차를 따른다. 이 문제는 주문 입력 복원으로 해결되어 버튼과 화면 배치를 유지하고 매수·매도의 선택 상태를 보조기기에도 전달했다.

## 격리 검증

- 4470에서 기존 `server/index.ts`와 빌드 결과를 사용했다. 빈 실행 환경에 `STOCK_DB=:memory:`를 주고 일반 한도를 실제 로컬 저장·재조회했다. 비교 예시는 `005930` 진입 후 직접 `000660 · 매도 · 4주 · 72,500원` 입력, 수동 한도 5→8 저장, 설정 새로고침 → 뒤로 → 앞으로 → 복귀 순서다. 복귀 후 수량 상한 8, 시세 조회 전 확인 버튼 비활성, 주문 POST 0회였다.
- 같은 4470에서 기준 main의 정적 빌드와 수정 빌드를 비교했다. 처음에는 10건 중 8건이 실패했고 단순 미확인 보존 2건이 통과했다. 확정 거부와 응답 유실 직후의 설정 재진입까지 검사하자 기준 main에서 12건 모두 실패했다. 기준 버전의 방향 선택은 시각 클래스에서, 수정 버전은 접근성 선택 상태에서 읽었다.
- 수정 후 전용 Playwright 검사 12건 통과. 두 크기에서 위 순서, 독립된 두 주문 이력, 현재 이력 수정·새로고침 및 같은 라우트의 새 폼, 타 종목 복귀 키, 전송 응답 유실 경계를 확인했다. 합성 시세·응답 유실 시나리오에서 화면 이동에 따른 재전송은 0건이었다. 다른 입력으로 왕복해도 확인창은 원래 미확인 요청을 표시했다. 명시적 재시도 1회는 동일 페이로드로 예시 접수를 받았고 별도 폼은 유지됐다. 확정 거부 시에는 수정할 입력이 새로고침 후에도 남았다.
- 관련 주문·취소·설정 브라우저 검사 20건과 TypeScript·프로덕션 빌드 통과. 별도 포트를 여는 설정 테스트 1건은 로컬 4470 검사에서 제외했다. Graphify는 `Paper.tsx`의 호출 관계를 확인한 후 `PYTHONHASHSEED=0 graphify update .`로 재생성했다.
- 지정 Gemini 4 Neon High 설계 검토에서 복귀 후 편집의 이력 분리, 새 수량 한도와 미확인 요청의 구분을 확인 항목에 반영했다. 구현 검토의 P2 세 건 중 전송 직후 재저장과 확정 거부 복구를 수정했다. 기본 종목 복귀는 설정 링크가 항상 종목 쿼리를 보내므로 기존 동작을 유지하고 `/paper?code=005930`을 실측했다. 수정분 재검토에서 동일 값으로 별도 주문을 시도해 확정 거부된 경우의 복귀 키를 추가 복구했다. 미확인 요청 재시도에 4xx가 오면 차단을 해제하라는 P1 제안은 #14 계약에 따라 기각했다. 재시도의 거부 응답만으로 최초 전송 결과를 확정할 수 없어 원장 대조까지 기존 요청을 보존한다. 전용 재현과 기존 `paper definitive preflight rejection permits correction but ambiguous retry stays pinned` 회귀를 통과했다. 최신 CI 판정은 [이슈 인계 기록](https://github.com/krdn/gon-stock03/issues/154)에서 확인한다.
