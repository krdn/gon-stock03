# #107 전용 KIS 모의 주문 테스트

프로젝트 루트에서 다음 명령으로 현재 연결과 설정을 조회한다. 11월 18일 16:04 실제 모의 잔고 전체 조회가 성공했고 전용 원장 주문은 0건이었다.

```sh
infisical run --env=dev --path=/kis -- npm run -s vts:test -- status
```

같은 명령의 마지막 인자를 바꿔 사용한다.

| 인자 | 동작 |
|---|---|
| `submit JSON` | 한 주문을 명시적으로 전송한다. JSON 필드는 requestId(UUID), code(6자리), side(buy/sell), qty, price. 시장가는 orderType=market과 price=0 |
| `batch < orders.jsonl` | 파일에 한 줄당 한 주문을 적고 순차 실행한다. 거절·결과 불명에서 중단한다. 동일 주문 재확인 시 원래 requestId를 유지한다 |
| `orders` | 증권사 내역과 전용 원장을 대조하고 전용 주문의 체결·잔량을 표시한다 |
| `inspect UUID`, `confirm < 확인.json` | 번호 없는 불명 주문을 조회한다. 모바일과 유일 후보를 대조한 뒤 id·evidenceId·brokerId·organization·confirmed=true를 입력해 최신 상태를 다시 확인한다 |

이 실행기는 실제 KIS 모의 서버에 주문한다. 회당 재승인, 이전 전략 계약의 횟수·금액 상한, 신호의 5초 제한을 적용하지 않는다. 주문 목록은 사용자가 직접 제공한다. 자체적으로 시세를 구독하거나 매매 신호를 생성하지 않는다. 같은 요청 ID는 중복 전송하지 않는다. KIS 거래시간과 계좌 가능 여부, API 호출 간격, 결과 불명 복구는 적용한다. 계좌별 원장은 이 체크아웃의 `.local/vts-test-runner/` 아래에 두고 프로세스 간 동시 쓰기를 직렬화한다. 기존 앱의 원장과 테스트 주문 기록은 별개지만 증권사 모의 계좌의 보유·미체결은 공유된다.

현재 실행 중인 앱에서 `/risk`의 회당 금액·종목별 투자금·공통 손실 한도는 DEMO와 일반 KIS 경로에 함께 적용된다. `/strategies`에서는 종목·단기/장기 평균·회당 수량을 정한다. `/settings`는 연결·잔고 확인을 제공한다. 세 화면에는 전용 실행기 설정, 신호 유효시간, 전략 계약별 횟수·누적금액을 변경하는 입력이 없다. 일반 경로의 수용 여부는 [#106](106-strategy-preflight.md)과 [#25](25-validation.md)의 증거로 판정한다.
