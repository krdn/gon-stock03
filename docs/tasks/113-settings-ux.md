# KIS 연결·설정 화면

[이슈 #113](https://github.com/krdn/gon-stock03/issues/113) · 브랜치 `krdn/improve-settings-ux`. 기존 [연결 복구 계약](71-settings-recovery.md)을 유지한다. 관련 구현은 `src/pages/Operations.tsx`의 Settings와 `tests/browser/settings.spec.ts`다.

4303에서 필수 값이 누락돼도 잔고 확인 버튼이 활성화됐고, 상단에 합성 데이터라고 표시됐다. 390×844 화면에서 사용자는 연결 방법을 열기 위해 페이지 상단에서 1,895px까지 내려가야 했다. 설정 누락·형식 오류를 버튼 바로 위에 표시하고, 안내 열기와 로컬 상태 갱신을 제공한다. 모의 잔고 확인은 설정 오류가 해소되면 활성화된다. 일반 진단과 서버 상세는 버튼 아래에 둔다.

## 4303 실측

| --- | --- | --- |
| 1440×900 | 526 → 432 | 1275 → 432 |
| 390×844 | 1895 → 424 | 1551 → 476 |
| 320×740 | 1951 → 461 | 1606 → 513 |

세 크기 모두 Enter로 안내를 열고 Space로 닫았다. 가로 넘침과 JS 예외는 0건이었다. 로컬 상태 새로고침 결과를 확인했고 각 세션의 API 요청은 `GET /api/state` 3회였다. axe 자동검사는 각 크기에서 안내를 열고 닫은 6개 상태 모두 위반 0건, 미완료 0건이었다. [모바일 수정 전](../verification/assets/settings-ux/mobile-before.png) · [수정 후](../verification/assets/settings-ux/mobile-after.png)

## 회귀와 리뷰

- 타입 검사와 Vite 빌드 성공. 단위 234개와 메모리 DB를 사용하는 Playwright 전체 157개 통과.
- 격리 환경에서 형식 오류 복구, 인증 대기·타임아웃, 조회 성공·실패와 이전 잔고 표시를 확인했다. 실제 KIS 인증·잔고 조회와 주문은 실행하지 않았다.
- Argon 독립 리뷰에서 P1~P3 지적 0건. 요청과 init 모델은 `gemini-4-argon-high`, 요청 effort는 high였다. 제공자 내부 모델과 effort의 별도 확인값은 없다.
- PR의 application/configuration 검사와 병합 상태는 이슈의 PR 링크에서 확인한다.

## 일반 개발 서버의 자동 주입

사용자 요청으로 `npm run dev`의 시작 스크립트가 Infisical CLI에서 모의 계좌 필수 값 4개를 이름으로 조회한다. API 자식 환경에 값을 넣고 웹 자식 환경에서는 KIS·Infisical 변수를 제거한다. 네 값이 이미 있으면 재조회하지 않는다. 일부만 있으면 Infisical 쪽 전체 집합과 일치하는 항목을 확인한 뒤에만 채운다. 실패하면 로컬 데모와 설정 화면에서 복구할 수 있다. 실시간 접속키 발급은 기존 명시 실행을 유지한다.

- 원본 실행 폴더 `/home/gon/llm-projects/gon-stock03`에도 실행 코드와 안내를 적용했다. KIS 변수를 제거한 환경에서 실제 `npm run dev`, 기존 CLI 로그인, 메모리 DB로 검사했다. 4303의 GET 응답은 `configured=true`, 필수 설정 `present`, 인증 `unverified`였다.
- API 프로세스의 필수 값 4개 존재, 웹 프로세스의 KIS·Infisical 변수 0개, API의 주문 승인·전략 계약·WS 접속키 미주입을 확인했다. Chromium 설정 화면에서 ‘필수 값 있음’, 조회 버튼 활성화와 `npm run dev` 안내를 확인했다. KIS 업무 호출·주문·영구 원장 접근 없이 검증용 프로세스를 종료했다.
- 빌드·단위 242개·설정 Playwright 16개 통과. CLI 미설치·권한 거부·불완전하거나 손상된 응답·기존 값 충돌을 포함한다. 변경 SHA와 원격 CI는 PR #114에서 확인한다.
- 이번 시작 스크립트 변경도 지정 Argon 독립 리뷰를 받았다. 요청·init `gemini-4-argon-high`, 요청 effort high, P1~P3 지적 0건. 공급자 내부 effort는 별도 미확인이다.

## 인증된 계좌의 잔고 갱신 동선

4303을 제공하는 원본 실행 폴더에서 확인했다. 모의 계좌 인증이 유효하고 마지막 잔고가 오래된 상태였지만 기존 화면은 ‘연결 확인 필요’를 표시했다. 상단에 ‘잔고를 다시 조회하세요’와 ‘모의 잔고 조회’ 버튼을 배치하고 설정·인증·잔고 상태를 분리했다. 이전 잔고에는 기준 시각과 ‘이전 조회 잔고’를 표시한다. 보유 종목의 수량·평균 매입가·현재가는 좁은 화면에서 종목명 아래에 배치한다. 정지 중이거나 서버 상태가 불명인 경우 긴급정지 안내는 상단에 유지한다.

| --- | --- |
| 1440×900 | 1084 → 380px |
| 390×844 | 1274 → 325px |
| 320×740 | 1353 → 362px |

[모바일 수정 전](../verification/assets/settings-ux/stale-mobile-before.png) · [모바일 수정 후](../verification/assets/settings-ux/stale-mobile-after.png). 변경 후 캡처의 계좌 금액과 보유 종목은 가렸다.

세 크기에서 실제 4303의 안내·서버 상세를 키보드로 조작하고 서버 기록 갱신을 확인했다. 브라우저 API 요청은 GET /api/state뿐이었다. 페이지 가로 넘침과 JS 예외 0건. axe WCAG 자동 검사에서 두 펼침 영역을 닫고 연 상태 모두 위반 0건이었다. KIS 잔고 조회·주문은 실행하지 않았다. 조회 성공·오류·대기·부분 수신·과거 금액 유지와 작은 화면은 격리 응답으로 검증했다.

빌드·단위 242개·관련 브라우저 테스트 48개가 통과했다. 이번 화면 변경의 지정 Argon 독립 리뷰 P1~P3 지적 0건. 요청·init 모델은 gemini-4-argon-high, 요청 effort는 high였고 공급자 내부 effort는 확인할 수 없었다. 원격 검사 결과는 PR #114에 연결한다.

## Opus 5.5 병합 리뷰

후보 `0574d65`의 코드와 PC·모바일 화면을 검토한 Opus 5.5의 첫 판정은 REQUEST_CHANGES였다. 토큰 발급이 거절되면 재시도 제한이 60초간 걸리는데, 대기 안내가 권한 오류의 복구 방법을 가렸다. 이 조합으로 기존 브라우저 테스트가 실패하는 것을 확인하고 실패 원인과 조치를 먼저 표시하도록 수정했다. 남은 시간과 조회 잠금은 유지한다. [수정 후 모바일 화면 (격리 응답)](../verification/assets/settings-ux/permission-cooldown-mobile.png)

설정 배지는 필수 값 존재를, 인증 배지는 토큰 발급을 표시한다. 서버 새로고침 결과는 5초 뒤 지우며 상세 시각에는 한국시간을 명시한다. 잔고 요약의 행동 안내와 공통 관측 기록의 상태명은 각각의 용도에 맞게 유지했다.

수정 후 설정 브라우저 18개, 단위 249개와 빌드가 통과했다. 실제 Infisical 로그인으로 격리 포트와 메모리 DB에서 개발 서버를 시작해 API의 필수 값 4개와 웹의 관련 환경변수 0개를 확인했다. 4303에서 3개 너비의 키보드·GET 새로고침과 가로 넘침, 접근성 자동 검사를 재확인했다. 실제 KIS 인증·업무 호출·주문은 실행하지 않았다. 수정분의 Opus 판정과 최종 CI·병합 SHA는 [이슈 #113](https://github.com/krdn/gon-stock03/issues/113)과 [PR #114](https://github.com/krdn/gon-stock03/pull/114)에 기록한다.
