krdn/gon-stock03의 화면 시각화 문서를 생성하거나 갱신하라. 한국어로 작성한다. 사용자가 지도에서 화면 하나를 골라 “무엇을 보고, 무엇을 누르면 어디가 바뀌며, 어느 지점에 질문을 남길까?”를 이해하는 것이 목표다.

1. 대상과 원본 찾기
- 현재 Orca 프로젝트와 worktree의 Git origin이 krdn/gon-stock03인지 확인하고 불일치하면 중단한다. AGENTS.md, docs/STATE.md, docs/WORKFLOW.md와 지도 이슈 #143·PR #144의 최신 상태를 대조한다. 2차 비교가 필요할 때 #149와 통합 후보 #187의 실제 head·검증 기록을 읽는다. 이미 끝난 PR 번호나 예전 포트를 현재 상태로 추정하지 않는다.
- 기본 대상은 기존 화면 지도다. 화면·기능이 지정되면 해당 카드와 영향을 받는 연결만 다룬다. 지정이 없으면 src/App.tsx, src/specs.ts, 실제 메뉴와 매매 설정 하위 경로를 대조해 누락되거나 설명이 달라진 카드를 찾는다. 변경 근거가 없으면 현재 지도의 링크와 점검 결과를 보고한다.
- docs/v1-guide.archify.md(편집 원본), docs/architecture/render-v1-guide.py(생성기), docs/tasks/143-v1-guide.md(검토 목차)의 소유 checkout과 기준 SHA를 찾는다. main에 없으면 #144의 최신 원본부터 확인한다. 같은 카드·주제에 대한 열린 후속 PR, 브랜치, 실제 작업 세션과 소유권을 먼저 대조한다. 인계받은 자기 작업이면 기존 worktree와 PR을 재사용한다. 타인이 같은 작업을 진행 중이거나 소유권이 불명확하면 위치와 상태만 보고한다. 새 작업은 원본 head SHA에서 자기 브랜치·worktree를 만든다. 조회 실패나 원본 누락 시 새 문서로 우회하지 말고 확인 가능한 범위만 보고한다. 명시적으로 별도 문서를 요청했고 주제·산출물이 기존 지도와 겹치지 않을 때는 새 이름의 원본과 HTML 경로를 사용한다.

2. 근거에서 사용자 설명 만들기
- Graphify의 explain 또는 path로 화면·컴포넌트·API·저장 위치의 연결을 찾아 제품 기준 커밋의 원문과 대조한다. 그래프의 추론·오래된 연결만으로 버튼 동작을 단정하지 않는다. Graphify가 없거나 기준이 오래됐으면 해당 커밋의 소스와 검증 기록으로 교차 확인하고 사용 한계를 표시한다. 1차 당시 코드, 현재 main, 2차 후보의 근거를 각자의 revision에 연결한다.
- 전체 목차는 기존 15개 메뉴와 별도 매매 설정 카드를 출발점으로 삼는다. 사용자 흐름도에는 종목·시세 → 주문 확인 → 주문 기록 → 보유 확인을, 시스템 구조도에는 앱 화면·PC 서버·로컬 원장·KIS 모의계좌의 역할을 표시한다. 범위가 작으면 해당 카드만 수정하고 기존 전체 구조·카드 ID·외부에서 공유한 앵커를 유지한다.
- 카드에는 ‘사용자가 궁금한 일 → 시점·환경이 적힌 화면 캡처 → 버튼의 동작과 결과 위치 → 현재 앱/2차 후보의 차이 → 다음 화면·코드 근거·피드백 이슈’를 연결한다. 보관 캡처는 원본을 보존한다. 최신 이미지가 필요하면 KIS 자격값·실제 원장을 연결하지 않은 격리 서버와 예시 데이터로 촬영한다. 화면에 중요한 정상·로딩·빈 상태·오류를 구분하고 미관측 상태는 표시한다. 비밀값·계좌 식별자·실제 주문번호가 들어간 원문이나 캡처는 산출물에서 제외한다.

3. HTML 생성과 검증
- 1절에서 소유권을 확인한 자기 작업 worktree에서 Python/Pillow, Node.js, 설치된 Archify의 경로와 버전을 확인한다. 그 worktree 루트에서 python docs/architecture/render-v1-guide.py <설치된 archify/bin/archify.mjs 경로>를 실행한다. 생성기는 캡처를 지도용 WebP로 줄이고 finalize explainer와 최종 HTML check를 거쳐 docs/architecture/figures/v1-guide.html을 만든다. 이 렌더러의 출력 경로는 고정이다. 별도 주제의 새 문서에는 이 고정 출력 렌더러를 실행하지 않는다. 고유 디렉터리에서 Archify explainer 원본과 로컬 캡처를 두고 finalize explainer 및 최종 check를 새 출력 경로에 적용하고 재생성 명령을 기록한다. Python/Pillow·Archify 의존성 누락은 설치 상태를 확인한 뒤 생성 미검증으로 보고한다. HTML만 손으로 고치지 않는다.
- HTML을 파일로 열어 이미지와 다이어그램 표시를 확인한다. 복사·탐색 검사는 완성 파일만 둔 전용 디렉터리를 비어 있는 임시 루프백 포트에서 제공해 수행한다. 1440×900 및 390×844 브라우저에서 목차→카드→목차, 기존 고유 주소 재접속, 글자·연결선 가독성·가로 넘침, 캡처 대체 텍스트와 키보드 포커스, Ask → Copy question으로 복사한 내용에 질문·카드 정보가 있는지 확인한다. 클립보드 권한 거부 시의 안내 또는 직접 전달 경로도 확인한다. 등록한 피드백 이슈를 확인하되 테스트 댓글을 전송하지 않는다. 앱 예시 링크는 허용된 로컬 격리 서버에서 기대한 화면 제목까지, 의견 링크는 해당 이슈와 일치하는지 확인한다. 서비스가 없거나 검증하지 못한 항목은 따로 기록한다. 임시 포트에서 제공한 HTML과 검증한 파일의 해시를 비교한다. 기존 4328 지도와 4303 앱은 읽기 대조만 한다.
- push 직전에 원본 브랜치 head와 소유권을 다시 확인한다. 원본이 달라졌으면 새 변경을 대조·반영하고 다시 검증한다. 변경한 원본·가이드·HTML과 필요한 캡처만 자기 브랜치에 커밋·푸시한다. 후속 PR의 base는 기준으로 삼은 원본 브랜치(main 또는 열린 지도 PR의 head 브랜치)로 맞춘다. 기존 자기 PR과 인계 댓글이 있으면 갱신하고 중복 PR·댓글을 만들지 않는다. 검증한 HTML과 원격 Git 파일의 SHA-256을 대조하고 사용한 도구 버전과 명령을 기록한다. 자신이 띄운 임시 서버만 정리한다. 변경이 없으면 기존 링크로 보고한다. 결과는 ‘대상 카드 / 문서 원본·제품 main·해당 후보 각각의 기준 SHA / 전후 차이 / 열 수 있는 지도·예시 / 검증과 미검증 / 의견을 남길 이슈’로 전달한다. 기존 지도와 기록을 갱신하는 것만으로 충분하면 독립된 중복 지도를 만들지 않는다.

이 명령은 시각화 문서 작업에 한한다. 제품 페이지 업그레이드, 다른 총괄 명령·worker 실행, 검토 중인 타인 PR의 직접 수정, main 병합, 실행 중인 4303·4328 교체, KIS 서버에 대한 주문·정정·취소(모의 포함)·전략 기동 및 원장 변경을 승인하지 않는다. 질문 복사나 의견 링크 검증 과정에서 사용자 명의의 댓글을 게시하지 않는다.
