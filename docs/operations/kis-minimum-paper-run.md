# #9 최소 모의 실행 승인안

**조건부 승인·미실행.** 2026-11-16 사용자는 아래 범위에 “수동 취소 대안에 동의”, “조건부 모의 주문 1회 승인”으로 각각 응답했다. 지금 실행하거나 예약하는 승인은 아니다. [공식 계약·대안](../research/kis-order-recovery-2026-11.md)과 [검증](../verification/2026-11-15-kis-orders-recovery.md)을 먼저 확인한다.

## 승인 범위

| 항목 | 허용 상한·조건 |
| --- | --- |
| 환경 | 현재 Infisical `dev /kis`의 KIS 모의 계좌 1개. VTS·KRX만. |
| 종목·방향 | [`069500` KODEX 200](https://www.samsungfund.com/etf/product/view.do?id=2ETF01) 현금 매수. 투자 판단이나 수익 검증 목적이 아니다. 실행 전 공식 마스터·현재가의 종목 일치를 확인한다. |
| 수량·횟수 | 1주, 주문 POST 총 1회. 응답 불명·거부라도 다른 요청 ID로 다시 보내지 않는다. |
| 금액 | 주문대금 최대 100,000원. 미수 없는 가능금액·현금이 주문대금보다 커야 한다. 한도를 맞추기 위한 증액·대체 종목은 금지한다. |
| 가격 | 실행 직전 KIS 현재가를 지정가로 사용한다. 호가 단위·상하한가·거래정지와 가격 나이를 확인한다. 가격이 100,000원을 넘거나 5초 내 시세를 얻지 못하면 중단한다. 시장가·정정 없음. |
| 실행 창 | 공식 개장을 확인한 하루의 10:00–10:10 KST에 별도 수동 시작 1회. 특정 날짜와 시작 지시는 아직 정하지 않았으며 지금 실행하거나 예약하지 않는다. |
| 잔량 | 30초 대조 후 잔량이 있으면 사용자가 같은 모의 계좌의 공식 앱에서 잔량만 수동 취소한다. 웹 취소 POST는 사용하지 않는다. 이후 REST로 잔량 0과 최종 체결수량을 확인한다. |
| 종료 | 접수 후 신규 주문 정지. 최대 120초까지 조회하고, 미확정이면 불명·정지 상태를 유지한다. 체결분 매도·반복 실행·전략 시작은 범위 밖이다. |

[KRX 정규장·휴장 규칙](https://global.krx.co.kr/contents/GLB/06/0602/0602010201/GLB0602010201T1.jsp)은 09:00–15:30과 휴장 예외를 안내한다. 평일이라는 이유만으로 실행하지 않는다. 실행일의 공식 휴장·특별 개장 공지 확인과 앱의 장 상태를 함께 확인한다. 실제 공식 달력 데이터 수집·검증은 완료하지 않았다.

## 실행 전후 절차

1. #9의 2026-11-16 사용자 승인 기록과 위 범위를 대조한다. 같은 범위의 승인을 다시 요청하지 않는다. 범위 변경은 별도로 결정한다.
2. 승인 대상 커밋의 CI와 단일 서버·단일 원장 경로를 확인한다. 기존 원장을 백업하고 `.codex/config.toml`은 보존한다.
3. [Infisical 지침](../INFISICAL.md)으로 주입한다. 키·계좌번호·토큰·응답 원문을 로그나 PR에 저장하지 않는다.
4. API 모의 계좌와 공식 앱 계좌가 같고 앱에서 잔량 취소가 가능한지 사용자가 확인한다. 확인 불가면 주문하지 않는다.
5. 잔고·전체 주문을 조회한다. 미확정 주문, 기존 미체결, 대상 종목 보유, 위험 정지·손실 한도, 연결 오류가 있으면 중단한다. 위험 설정을 자동 완화하지 않는다.
6. 새 UUID 1개와 정확한 단가를 지정해 기존 `POST /api/kis/order`를 한 번 호출한다. 서비스가 `sending`을 원장에 먼저 저장한 뒤 전송한다. 원장에 주문을 수동 선삽입하지 않는다. 실제 전송 시각도 실행 창 안이어야 한다.
7. 응답과 무관하게 신규 주문을 정지하고 REST 조회만 진행한다. 접수번호와 거래일·조직·종목·방향·수량·가격을 대조한다. 네트워크·계약·수량 불일치면 자동 재전송 없이 중단한다.
8. 잔량 처리는 위 수동 취소 조건에 따른다. 체결·취소 ACK만으로 완료를 선언하지 않는다. 미관측 취소·부분체결·경합은 #25 V01에 별도로 남긴다.
9. 민감값을 제거한 접수/대조 시각·상태·체결/잔량·대상 SHA·감사 ID와 사용자 관측을 #9에 기록한다. 사용자 육안 수용과 fixture 결과를 구분한다.

조회에 없는 번호 없는 불명은 자동 해제하지 않는다. 명시적 복구를 하려면 원래 계좌·주문 근거를 확인하고 inspect→confirm 절차를 별도로 수행한다. 이 1건 실행 승인은 임의의 기존 불명 해제 승인까지 포함하지 않는다.

## 승인과 남은 실행 조건

- 사용자는 웹 취소를 보류하고 **공식 모의 앱 수동 취소 + REST 대조**로 최소 실증하는 대안에 동의했다. 웹 취소의 409 차단을 해제하거나 지원 완료로 표시하지 않는다.
- 사용자는 위 1주·100,000원 상한·주문 POST 1회·시간창·정지 조건을 승인했다. 미체결·거부·불명이어도 주문 재전송, 매도, 정정, 반복 전략은 승인하지 않았다.
- 실행일, 공식 개장, API와 앱 계좌의 일치, 앱에서 잔량 취소 가능 여부, 최신 시세·잔고·원장, 시간창 내 별도 수동 시작을 확인해야 한다. 이들은 아직 확인하지 않았다. 실행 전 조건이 모두 충족되기 전에는 전송하지 않는다.
- 지금은 실행 준비 점검만 진행한다. 예약·상주 대기·실제 KIS 업무 인증/조회/주문/취소 호출은 수행하지 않는다. 준비 결과와 실제 접수·조회 증거를 구분하며 #9 OPEN/Blocked와 후속 차단을 유지한다.
